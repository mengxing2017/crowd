# 文档站使用与维护

文档站参考 huavd-map-build/docs 的 VitePress 组织方式，提供首页、分类导航、页内目录和本地全文搜索。文档可独立启动，无需数据库、API 或前端应用。

## 启动查看

在仓库根目录执行，环境为 Node.js 22、pnpm 10.12.4：

```bash
make docs-install
make docs-dev
```

浏览器访问 http://127.0.0.1:5174。修改 Markdown 后自动更新，按 Ctrl+C 退出。也可直接在 docs 目录执行 `pnpm dev`。

默认仅监听本机。端口占用时会报错，不会静默切换；换端口或供局域网访问时显式执行：

```bash
pnpm --dir docs dev --host 0.0.0.0 --port 5175
```

## 构建与预览

```bash
make docs-build
make docs-preview
```

预览地址 http://127.0.0.1:4174。静态产物为 `docs/.vitepress/dist/`，可部署到站点根路径；子路径部署前需在配置中设置对应 `base` 并重新构建。当前 Compose 不部署文档服务。

构建执行内部链接检查，失败时应修复引用，不要全局关闭死链检查。安装使用 `docs/pnpm-lock.yaml`；升级依赖后提交更新的锁文件。

## 文档组织

| 目录 | 内容与维护规则 |
| --- | --- |
| `guide/` | 开发入口和文档维护说明；项目指南与根 README 的开发命令保持一致 |
| `requirements/` | 需求、实现、依赖与验证追踪，保留原阶段状态 |
| `adr/` | 按编号递增的架构决策；后续变化新增决策并关联历史记录 |
| `runbooks/` | 配置、操作、验证证据与未验证项 |
| `reference/` | API 契约引用页与中英文 MIT 协议 |
| `.vitepress/config.ts` | 分类导航、侧栏、全文搜索和站点配置 |

已有文档路径保留，根 README 和历史相互引用继续可用。新增页面时同步分类索引与侧栏；跨页面链接优先使用相对 Markdown 路径。API 契约页通过 include 引用 `api-contract/README.md`，避免维护两份契约正文。

文档必须自包含：需求范围、参数边界、依赖及验证依据直接写在 `requirements/`，其他页面链接到对应追踪表，不依赖站点目录之外的需求文件。新增需求内容时须区分已确认规则、建议及待验收项。不要将凭据、收款资料、私有图片或真实人工凭证放入文档和构建产物。
