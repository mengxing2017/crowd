# M17–M19 收款资料与人工异常运行手册

范围与验收核对见 [需求追踪](../requirements/m17-m19.md)。没有支付接口或真实资金池；人工凭证不是官方到账证明。

## 配置与用户操作

1. 按 [嵌入式 PostgreSQL 手册](embedded-postgres.md) 启动 API 和 Web。文档可独立运行 `make docs-dev`。
2. 规则管理员在“提现申请规则”编制新版本，另一复核人员发布。启用支付宝需填写政策依据并确认，显式选择允许手机号／邮箱格式及姓名是否必填。未配置完整政策时账户仅存草稿，不能申请。
3. 图像清理策略需填写正整数保留秒数与依据，独立发布。期限以文件上传时间计算，不存在正式默认期限；未配置不执行清理。
4. 用户在小程序选择／拍摄微信码，可点击预览放大，检查清晰、完整及无遮挡；本人声明后保存新版本。支付宝填账户及必要姓名并确认；不得填支付密码或验证码。
5. 默认资料取每种方式最新有效确认版本。新版本不覆盖旧申请，申请固定版本并另记确认时间。停用阻止新申请选择，历史申请原文仍受限保存。
6. 已停用微信码显示清理入口。清理只删除超过配置期限、无其他资料／全部历史申请／核查保全引用的二进制；有引用返回 `RETENTION_PROTECTED`。同请求键重试返回原结果，不新增清理事件。

## 经办查看与异常处置

- 授权人员在具体申请详情填写用途后查看固定快照或凭证。当前独占经办在本单数据范围内处理；运营与未领取经办不得因此读取其他申请敏感资料。
- 支付宝复制按钮再次授权读取并以“复制账户”用途留痕。图片先通过授权请求取得临时浏览器地址，可放大或下载；关闭详情释放页面图片引用，下载会重新授权并以“下载核对”用途留痕，不产生永久公开链接。
- 经办点击“分类登记异常”，选择资料错误、尚未付款、结果不明或登记错误，填写有本单范围的核查经办编号与说明。分类后保留占用；指派责任人不改变原独占经办，交接仍需双方确认。
- 资料错误：停止处理并人工确认是否已经线下付款。确认未付款且停止处理后退回，用户更正资料并重新申请；不得替换原申请快照。错误类别不能降级绕过。
- 尚未付款：继续核查或由原独占经办确认未付且停止处理后释放。结果不明：在系统外人工核查，不自动查单、重付或超时释放。
- 登记原结果时填写整数分、付款时间、私有凭证，可填必要流水备注；异常后勾选已核查原结果。登记超时查询原请求或原键重试，不再次线下付款。
- 登记错误走关联更正及独立复核；原凭证和结论保留。已结算不自动追回或抵扣未来佣金。复核、结转和未付释放沿用 [M13–M16 手册](m13-m16.md)。

## 新增接口与兼容字段

- `POST /api/v1/community/commands/receipt_cleanup`：本人 `id`、当前用户 `version`、`reason`；使用原幂等键。越权、未停用、有引用或无明确策略均拒绝。
- `POST /api/v1/community/commands/settlement_exception`：申请 `id`、`version`、`kind`、`assignee`、`reason`；须独占经办及数据范围。
- `settlement_register` 新增 `offline_result_confirmed`（分类异常后必需）和可选 `reference_note`。收款方式仍从原快照取值，不能由客户端改付。
- `receipt` 响应增加资料 `status`；记录增加 `declaration_version`、`confirmed_at`、可选 `policy_id`；列表推导 `is_default`。申请增加 `receipt_confirmed_at` 和可选分类 `exception`。新增字段为兼容扩展，旧接口路径保留。

## 验证记录

执行环境：Rust 1.97.1、Node.js 22.17.0、pnpm 10.12.4（复用既有安装依赖，关闭自动切换 pnpm 11），一次性嵌入式 PostgreSQL 17。

- `make check-web`：契约类型／运行时响应校验、原键及领域边界检查、Web／小程序类型检查、Lint 和构建通过；本次使用 `npm_config_manage_package_manager_versions=false npm_config_package_manager_strict=false` 复用现有 pnpm 10 依赖。
- `devbox run -- make test-business`：2 个真实隔离 PostgreSQL 集成测试通过，新增保留期内拒绝、历史引用保全、越权、清理幂等，以及状态写入异常时图片删除回滚及原键恢复。
- `pnpm --dir frontend --filter @crowd/web exec playwright test tests/finance.spec.ts`：4 个 Chromium 浏览器场景通过，包含异常分类／责任人、错误资料登记入口隐藏、岗位隔离、配置及原请求重试；使用相同 pnpm 环境变量。
- `make docs-build`：站点构建及内部链接检查通过；30 条需求编号检查通过，docs 不依赖外部需求目录。
- `devbox run -- make check-backend`：格式、编译、全部目标 Clippy（警告视为错误）及 75 个非数据库测试通过；默认跳过的 2 个数据库测试已由上述隔离入口实际执行。
- `git diff --check`：通过。

微信真机、正式保留政策、实际外部人工付款、浏览器敏感下载／剪贴板权限及业务签收尚未验收；不声称官方到账验证。清理未覆盖进程强杀和存储损坏恢复，当前全局状态锁的规模压力未验证。
