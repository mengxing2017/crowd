# M01–M04 运行与验证

日期：2026-10-27；代码交付不等于业务验收。逐条追踪见 [需求对应表](../requirements/m01-m04.md)，架构取舍见 [ADR 0002](../adr/0002-identity-profile-promotion.md)。

## 部署与首次配置

1. 本地开发运行 `devbox run -- make api-dev` 自动创建隔离嵌入式 PostgreSQL；持久化/部署使用外部 PostgreSQL 并设置 `CROWD_DATABASE_URL`（本地外部入口为 `make api-external`）。启动自动执行 0001、0002 forward-only migration。迁移失败阻止启动。数据库需允许创建 pgcrypto 扩展；不需要支付相关凭据。
2. 服务端配置 `CROWD_WECHAT_APP_ID`、`CROWD_WECHAT_APP_SECRET`。缺失或微信校验失败时拒绝登录，不提供开发身份 HTTP 后门。不要把 AppSecret 放进前端或日志。
3. 首次空环境设置 `CROWD_BOOTSTRAP_PLATFORM_ID=AppID:OpenID`，仅对应可信微信身份可以建立首个管理员。此值由运营控制面安全配置，不通过客户端输入建立可信身份。首次建档后立即移除该配置。
4. 小程序 manifest.json 设置微信 AppID；构建时设置 `VITE_API_ORIGIN=https://实际API域名`。生产须配置微信合法请求/下载域名和 HTTPS。本地开发默认 `http://127.0.0.1:8080`，仅开发者工具使用。
5. 首个管理员在小程序生成一次性后台票据，60 秒内在 Web 登录。规则中心选择 `agreements`，保存 `{"service":"正式服务协议正文","privacy":"正式隐私说明正文"}` 草稿后单独发布；新注册必须主动同意对应版本。运维初始化不代表正式协议已经通过业务/法务确认。
6. 通过后台为实际岗位授予具体角色和数据范围。权限修改须包含目标用户编号、当前 version、roles、scope、reason；不能修改自己的授权。默认用户只能操作本人资料。
7. 设置 `CROWD_PROMOTION_ORIGIN=https://实际Web域名` 后启用普通二维码生成，Web 根入口支持 `?source=不透明码`。未配置时可复制码值，但二维码返回依赖不可用。

产品/任务目录例子（需替换为实际目录和已确认完成条件，不是预置业务数据）：

```json
{"products":[{"id":"实际产品编号","status":"active","tasks":[{"id":"实际任务编号","status":"active","completion":"实际完成口径","evidence":"实际证据要求"}]}]}
```

保存为 `product_tasks` 草稿并发布；下架通过新版本将对应 status 改为 inactive。目录不等同完整任务执行能力。

## 接口与结果恢复

成功返回 `{data,request_id}`，失败返回 `{error:{code,message,request_id}}`；文件和二维码成功返回私有二进制内容及 `no-store`。JSON 与二进制上传当前最多 5 MiB。既有 `/api/v1/system` 契约保持不变。

| 方法及路径（共同前缀 `/api/v1/community`） | 用途 |
| --- | --- |
| GET `/agreements` | 当前已发布协议；未发布拒绝普通注册 |
| POST `/login` | 微信临时 code、主动同意、协议版本和可选来源 |
| POST `/session` | 原子兑换一次性后台票据 |
| GET `/read/me`, `/read/codes`, `/read/receipts`, `/read/cases` | 本人资料、推广码、脱敏资料及本人申请 |
| GET `/read/rules`, `/read/users?target=...`, `/read/managed_codes?target=...`, `/read/audit?target=...` | 对应岗位与数据范围内的后台查询 |
| GET `/read/command_result?target=原请求键` | 查询本人原已提交结果，重新检查当前动作权限 |
| POST `/commands/{action}` | Bearer 会话及 Idempotency-Key；同键同内容返回原结果，同键不同内容冲突 |
| POST `/files/avatar`, `/files/wechat_receipt` | 原始 PNG/JPEG 字节；用途独立、私有保存 |
| GET `/files/{id}` | 本人授权查看，完整访问留痕 |
| GET `/qr/{code}` | 本人有效推广码 PNG |
| GET `/resolve/{code}` | 无敏感信息的公开入口校验；不产生佣金 |

动作：profile、receipt、receipt_disable、receipt_reveal、code_create、code_rotate、rule_save、rule_publish、rule_disable、access、restriction、correction、merge、closure、phone（未启用）、web_ticket、logout。资料和授权修改携带当前 version；新规则版本携带该类型已有版本数。完整资料查看携带 reason；换码携带旧码 id/version、reason、approval 审批依据。审核记录中的实际操作者由会话决定。

超时保留原动作、内容和请求键，先查原结果；未查到时只重试原请求，不重新创建第二份提交。字段或权限等明确失败可修正后用新请求键重新提交。客户端内存状态在退出/重启后清除，会话过期需重新登录；不把未确认结果显示成成功。

## 自动验证

```bash
make check-web
devbox run -- make check-backend
# 自动创建并清理嵌入式测试库（推荐）：
devbox run -- make test-business
# 如需人工准备测试库，另建空的、本机专用 crowd_test_* 数据库后显式执行：
CROWD_TEST_DATABASE_URL='postgres://测试用户@127.0.0.1:测试端口/crowd_test_新的数据库' \
  devbox run -- cargo test --manifest-path backend/Cargo.toml --test community_postgres -- --ignored --nocapture
```

`test-business` 只向测试子进程注入新建临时库的 `CROWD_TEST_DATABASE_URL`，覆盖继承的外部测试库设置；运行结束停止数据库并清理数据。手动运行集成测试时只读取 `CROWD_TEST_DATABASE_URL`，要求本机地址及 crowd_test_ 前缀，且业务用户表为空；绝不回退到应用数据库。每次重跑应新建空测试库。默认后端检查明确跳过此需真实数据库测试，不把跳过当作通过。

本次实际验证环境：Linux x86_64、Rust 1.97.1、pnpm 11.22.0、PostgreSQL 17.11。数据库为 `/tmp/crowd-pg-validation`，仅监听本机 55439，数据库名 `crowd_test_01_04`（首轮）、`crowd_test_01_04_final`（最终轮），使用测试专用本机 trust 认证，不适用于生产。验证结果：

| 检查 | 实际结果 |
| --- | --- |
| `make check-web` | 通过：契约类型与运行时测试、两端类型检查、lint、Web 与微信小程序生产构建 |
| `devbox run -- make check-backend` | 通过：fmt、check、Clippy（warnings 视为错误）、11 项领域测试与 3 项 HTTP 契约测试 |
| 显式 PostgreSQL 集成测试 | 通过：并发注册、同键重放/异内容冲突、版本竞争、原结果查询、生成队列重复恢复、文件真实格式/用途/归属、脱敏、票据一次性、退出及到期拒绝 |
| HTTP + PostgreSQL 联合验证 | 通过：本人会话读取、跨用户文件拒绝、公开解析不泄露用户编号、授权二维码 PNG 可解码为图像并含黑白像素 |
| 文档检查 | 通过：本次文档本地引用有效，40 个需求编号与四份 report 一致 |

最终联合验证使用独立空数据库 `crowd_test_01_04_http`，二维码配置为测试专用 `https://crowd.example.test`；不请求该测试域名、不产生真实归因以外的数字、不执行任何付款。二维码验证是 PNG 输出检查，未执行扫码内容的真机读取。验证结束后已停止本次临时 PostgreSQL；/tmp 测试数据与日志保留，未修改应用数据库。

## 未验证与业务依赖

- 未提供真实微信 AppID/AppSecret 和真机环境，未进行真实微信登录、相册权限与二维码跨设备扫描验收；自动测试只注入可信身份端口，不能称为微信官方认证测试。
- 未执行 Docker 镜像/Compose 发布和生产容量测试；不承诺单例聚合存储的上线吞吐。
- 尚无任务领取、佣金、提现、争议和人工付款模块，不能完成注销未结核查、在途资料纠错闭环或已登记结算的全链路验收。
- 手机号绑定策略、支付宝支持格式、资料正式限制、复核策略等仍待业务确认。当前安全拒绝或保留草稿，不静默固化建议。
- 无支付调用、付款调度、支付回调、自动查单或自动付款重试；图片解码和手工输入不证明官方到账或官方账户可收款。

## 后续人工验收步骤（本次未执行）

1. 用真实微信凭据分别验证普通新用户、重复登录、拒绝协议和协议更新后的注册；确认伪造用户编号不会改变服务端身份。
2. 两个不同微信账号互相尝试读取私有收款图和完整账户；确认拒绝。上传头像后将资源用作收款码应拒绝。修改/停用资料后核对旧版本仍保留。
3. 生成主码与两个产品定向码，修改昵称和重新登录后主码不变。发布停用产品的目录新版本后，旧入口公开解析应明确不可用；历史来源仍保留。
4. 在真机拒绝相册授权，仍可查看和复制推广码；检查微信原生错误是否需要进一步翻译为更具体提示。跨设备扫描二维码并核对 Web 落地页来源与小程序注册来源。
5. 以规则管理、客服、任务审核、推广管理与审计分别登录，核对角色和目标数据范围；无权限操作不能仅依赖页面隐藏。用过期票据、重复兑换与退出后的会话验证拒绝。
6. 模拟网络提交超时，通过原请求键查询结果或重试；会话失效后重新登录另一账号不能重放前一账号保留的操作。当前客户端只在内存保留待确认引用，重启后由对应后台查询辅助核对。
7. 接入任务、提现、争议和人工结算模块后，再验收注销未结核查、在途收款纠错停止处理与重新确认、历史申请快照及全链路来源；当前不得勾选这些依赖项已完成。
