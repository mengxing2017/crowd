# M08–M12 运行与验证

需求追踪见 [M08–M12](../requirements/m08-m12.md)，架构见 [ADR 0004](../adr/0004-task-pricing-evidence-review.md)。以下是工程交付说明，不是业务验收结果。

## 初始化和操作

1. 本地 `devbox run -- make api-dev` 使用嵌入式 PostgreSQL 17；启动自动执行 forward-only migration 0005，为旧聚合增加 tasks，并扩展私有文件用途。临时库正常退出即清理；不改为连接业务数据库运行测试。
2. 由身份审核人员为不同工作人员配置规则管理 `rule_manager`、产品运营 `operator`、任务审核 `task_reviewer`、独立复核 `verifier` 和必要的产品范围。规则编制者不能批准自己的版本，用户不能审核自己的任务。既有账号不通过 migration 自动扩权。
3. 后台“定价与任务模板”分别创建定价和模板，明确所有时限、资格、名额、频次、证据字段、风险复核及释放策略。另一人员独立批准。定价版本和模板内容不可覆盖，更新创建新编号。
4. 产品草稿填写已批准 `template_id`、`price_id`；内嵌任务编号与定价适用编号一致，显示固定佣金／可选比例封顶（未封顶为待核定，兼容数字填0）、完成条件与时限与批准版本一致。提交发布后仍由另一人员审核。比例规则必须明确适用人群、可信基数来源、舍入和有效期；封顶可选，无封顶时不得绑定要求最大数字预占的上限策略。
5. 小程序领取确认后进入“我的任务执行与提交”。开始并依次完成必做步骤，按领取时模板保存草稿、上传本任务私有证据、填写发生时间、精确预览及真实性确认。最终提交显示回执，重复同键不新建版本。网络结果不明先查询或用原键重试。
6. 后台“任务审核与质量”按产品范围查看队列，独占领取后按用途查看证据，填写审核原因及检查声明。可最终驳回、指定字段补交、通过；高风险初审后需另一人员复核。批量仅支持常规人工固定佣金任务，确认前校验每个版本和数字合计，一项异常整批失败。
7. 暂停／恢复保留原因及实际时长，依据快照顺延或维持期限。超时 worker 每30秒检查，动作前也检查；只影响未提交阶段，不把审核等待变为失败。审核 SLA 只提醒、不自动通过，通知按提交回执及待审阶段去重；待复核阶段通知具备产品范围的独立复核人员。
8. 状态修复、结论撤销必须提交理由与证据，再由独立人员批准；状态修复不能越过提交审核。已通过结论转争议只追加核查事件，不删除原数字确认、不外部退款或抵扣。抽检差异需另走此更正流程。

## 接口

继续使用带 Bearer、`Idempotency-Key` 的 `/api/v1/community/commands/{action}`，以及 `/read/{section}?target=...`。命令作用于实例时传 `id` 和当前 `version`，版本冲突刷新后重新确认，不能自动覆盖。

- 规则：`price_save/price_review`、`template_save/template_review/template_disable`；读 `task_rules`。
- 执行：`task_start/task_step/task_abandon/task_pause/task_resume/task_expire`。
- 证据：`evidence_save/evidence_discard/evidence_preview/evidence_submit/evidence_withdraw`。`evidence_submit` 必须传预览编号及 `confirmed=true`。`evidence_discard` 只清理当前草稿及未被任何本任务历史提交引用的附件，不删除历史提交；无背景自动销毁历史证据任务。
- 证据上传：`POST /api/v1/community/files/task_evidence:{claim_id}`，二进制真实 PNG/JPEG；只能向本人可编辑任务上传。文件按模板限制，并有每任务累计100个上传文件的工程资源上限；及时清理未提交草稿可释放未引用附件。
- 敏感查看：`evidence_reveal` 传用途原因；文件 `GET /api/v1/community/files/{file_id}?reason=...` 重新校验本人／本单经办／独立复核权限，工作人员不可查看未提交草稿图片，响应 no-store，不生成永久公开 URL。
- 审核：`review_claim/review_decide/review_verify`、`review_batch_preview/review_batch`，批量确认必须沿用预览的条目和版本。
- 更正：`task_repair_propose/task_repair_review`、`review_revoke_propose/review_revoke_review`、`quality_inspect`。
- 查询：`my_tasks`、`task_queue` 的 target 是 JSON 过滤器，可包含 status、task_type、risk、cursor、limit，页大小1–50；队列只显示待审状态和授权产品。`task_detail` 的 target 为实例编号。`task_changes` 仅平台审计岗位读取确认、更正和抽检依据。
- 稳定错误包括 INVALID_INPUT、FORBIDDEN、VERSION_CONFLICT、RULE_OVERLAP、QUOTA_EXHAUSTED、IDEMPOTENCY_CONFLICT、DEPENDENCY_UNAVAILABLE、VERIFIED_BASE_REQUIRED，并保留可读说明及追踪编号。规则冲突时查询批准版本的范围和时间，不能直接覆盖。

独立复核人员可仅授予 `verifier` 岗位进入待复核队列，无需额外授予初审权限。模板／定价审批仍要求平台范围；任务复核只要求对应产品范围。

## 未验证与上线边界

- 新版比例定价的“待核定／封顶”显示需要本轮客户端，旧客户端仅保留旧式快照兼容；上线前需核对客户端发布和存量版本，不把占位0当实际零佣金。
- 微信真机、弱网重开、摄像头／相册权限拒绝、图片阅读及业务人员完整验收尚未执行，uni-app 构建不能代替这些检查。
- 外部任务来源生产认证／验签适配器、真实成果基数及乱序集成尚未部署；内部端口测试不能宣称生产来源已经验证。
- M13 数字台账／可申请汇总、申请占用、人工线下结算仍未接入；`pending_ledger` 不能展示为可提现数字，也不提供支付、付款调度、自动查单、付款回调或补付重试。
- Docker／Compose、生产迁移演练、数据库进程中断／网络断连恢复演练、规模压力和性能指标尚未验收。全局聚合行锁的吞吐和持续增长需后续专项验证；旧客户端兼容保留不等于所有既有版本均完成真机回归。
