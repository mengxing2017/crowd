# 数字调整、活动计划、消息与客服风险操作

本手册用于 M20–M24 日常岗位处理。需求、实现边界和验证入口见[需求追踪](../requirements/m20-m24.md)。

## 启动与岗位

```bash
devbox run -- make api-dev
make web-dev
make docs-dev
```

开发使用隔离的嵌入式 PostgreSQL，默认退出后不保留临时库；需持久化开发数据时按[嵌入式数据库手册](embedded-postgres.md)配置独立开发库。不要连接生产库执行样例或故障注入。

| 岗位 | 操作 | 范围 |
| --- | --- | --- |
| operator | 活动建立、计划调整、归档、通知模板 | 活动／产品编号及 notifications |
| settlement_reviewer | 失效依据、调减／恢复申请、来源数字暂缓 | 用户编号 |
| verifier | 独立数字调整复核、数字暂缓解除 | 用户编号；不得复核本人提出的调整 |
| support | 工单转派、回复、结案、统计 | 用户编号 |
| rule_manager | 发布申诉次数／期限／重开政策 | support |
| risk_manager | 风险规则、必要人工关联核查、具体限制与解除 | 规则编号或核查用户编号 |
| auditor | 活动及数字记录核对 | 活动／用户编号 |

新建开发管理员包含 support 与 risk_manager；已有管理员不会静默增加岗位，可由授权的身份审核人员通过“用户与权限”设置。数字暂缓需要同时具有数字审核岗位；解除暂缓需要复核岗位，风险岗位不能替代这些权限。

## 任务失效与数字调整

1. 在“任务撤销与数字调整”指定用户、原任务、唯一依据号、业务来源和可核对说明。退款说明不执行退款。
2. 无法定位的依据进入待定位，由授权人员补充可信任务编号。定位后再次查询版本，不按昵称或模糊匹配调减。
3. 独立复核人核对原确认、调整数及依据。待审任务只取消待审标记；已确认任务追加调减。
4. 如显示在途或已登记申请，先处理人工核查，保留占用和原收款快照。已登记结算争议不自动追回，也不从未来数字扣除。
5. 未被经办领取的申请可由用户撤销，待审申请可经审核退回；已开始人工处理的申请只有确认未付款且已停止处理后，才能按原流程退回。不能直接清除占用。关联申请解决后重新查询调整版本再复核。
6. 已实际付款或原登记需继续复核时，先由数字复核人员在“佣金数字与流水”明确处理对应争议。只有本申请所有阻断来源争议均已复核，系统才解除调整暂停，原经办与收款快照保持不变；继续走原登记／独立复核，不再次付款。已经登记结算且争议结论明确的调整，可再次独立复核为争议记录结案，不能调减未来数字。
7. 原失效结论撤回时，登记“恢复”并指定原调减单。待审批与已审批恢复合计均受原调减上限控制。

批量处理先选择待复核条目预览影响人数、数字与申请清单；另一名复核人员查询原批次后确认。原条目版本变化会拒绝整个批次，不能部分成功后假装全部完成。超时使用页面原结果查询与原请求键重试。

## 活动计划与统计

创建活动时明确产品集合和存量负责人。未启用计划上限时无需填写真实到账或充值信息；启用时输入整数分计划上限。已执行占额与确认统计不能通过降低上限绕过。

不同活动间调整计划数字必须填写目标版本和原因，双方上限在同一事务更新。产品集合不能覆盖迁移，避免历史占额转移。归档前确认在途责任，归档仅停止新增领取，不关闭存量任务或清零用户数字。

活动统计中的“可申请”“在途申请”“已登记结算”都属于平台业务记录，不是银行余额或托管资金。

## 站内告知与外部订阅

任务、佣金、提现、工单和风险变化生成关联消息。用户看到历史通知时，应查看当前单据状态；已登记结算通知不作为官方到账证明。后台待办只返回岗位范围内的编号和状态，不展示收款原文。

运营发布模板时保留 `{business_id}`、`{status}`、`{notice}`，核对受控目标并确认预览。任务临期提醒需显式配置提醒窗口；未配置不擅自采用正式默认期限。

仓库默认只启用站内消息。外部通知接入需实现 `notifications::south::port::NotificationDelivery`，按稳定消息键去重，并使用 `DeliverNotification` 提交服务；不从浏览器上报“发送成功”。用户须先按模板主动授权，模板须显式配置最大尝试次数与重试间隔。未授权、临时失败、永久失败及重试耗尽分别记录；网络调用在业务事务外执行。发送失败不回滚佣金记录或人工登记。

## 客服工单与申诉

用户按分类选择本人的任务、流水、提现或风险单。客服核对关联业务后可转派队列、明确责任人、填写截止时间并回复；内部备注只对授权客服可见。附件必须由当前提交者上传，不允许引用他人上传文件冒充本人材料。

申诉次数、申诉期限和重开期限由规则管理员显式发布；未配置时先使用普通咨询。审核驳回申诉保存原审核人和政策快照；强制独立时原审核人不能结案。客服不得结案本人申请，不能直接修改佣金汇总。

结案说明应包含处理结论及下一步；需要数字修复时先走正式调整与独立复核，再关联调整单。用户按原政策期限重开，继续原证据与责任链。付款结果未知的咨询应写“待核实”，不能保证“已确认收款”。

## 风险核查与解除

发布规则时填写必要目的、样本评估、生效范围、失效时间及显式阈值。无规则时不默认启用频率限制或数字暂缓。

自动命中进入核查，不等于违规认定。账号关联仅登记必要且已授权业务信号；单一相同网络或集中访问不能直接封禁或暂缓全部数字。限制须说明具体新领取／新申请范围与有效期，到期不继续拦截这些操作。

需要暂缓数字时指定真实佣金来源和整数分，使用既有争议流水并执行额外数字审核权限校验。该暂缓不是外部资金冻结；解除需要数字复核权限和明确结论，不因时间推断付款结果。额外补记另走正式调整单。

## 验证命令

```bash
make check-web
devbox run -- make check-backend
devbox run -- make test-business
make docs-build
```

`test-business` 按既有身份／任务、财务、新增运营流程顺序使用独立嵌入式 PostgreSQL。新增测试含并发末份活动额度、原请求幂等、越权关联、数据库写入故障及恢复。测试不连接生产，也不验证真实支付到账。
