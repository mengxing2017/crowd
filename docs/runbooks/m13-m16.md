# M13–M16 运行与验证记录

依据 [四模块追踪表](../requirements/m13-m16.md) 与 [ADR 0011](../adr/0011-commission-withdrawal-manual-settlement.md)。平台数字不是存款，本文流程不调用微信／支付宝付款、查单或退款接口，也不证明实际到账。

## 启动及数据迁移

```bash
devbox run -- make api-dev
make web-dev
```

开发入口使用隔离的嵌入式 PostgreSQL 17，服务启动执行 migration 0001–0006。0006 仅扩展私有文件用途，不删除原收款资料、任务确认或申请。历史 `pending_ledger` 通过锁内加载及唯一任务／受益人／类型键衔接佣金流水，重复加载不重复增加；原始确认与计算快照保留。回退只能使用能保留这三个领域状态与凭证用途的兼容版本；不能直接启动会丢弃新增字段的旧二进制，不回滚 migration 或删除流水。新确认进入可申请数字计算，但仍受账户限制、争议、占用、已登记结算及已批准规则约束。

运行账户及数据与生产隔离。嵌入式开发数据库退出后清理，勿将其当长期业务记录存储；正式持久化配置沿用部署文档。

## 配置与岗位

| 用途 | 岗位／范围 | 约束 |
| --- | --- | --- |
| 提现规则草稿 | `rule_manager`，`platform` | 必填整数分门槛、单日次数／累计、累计上限、方式、提醒及复核策略，无默认正式门槛 |
| 规则独立批准 | `verifier`，`platform` | 不能自审；新发布取代当前规则，旧申请保留旧版本 |
| 数字补记、归属纠错／争议 | `settlement_reviewer`，目标用户 | 补记有唯一业务单、来源及依据；调减／转归属不得动用已占用或已结算数字 |
| 数字调整及争议核查 | `verifier`，目标用户／新受益人 | 调整由不同身份批准；争议解除只释放对应争议暂缓，不释放申请占用；有争议的申请释放后，原来源数字继续转为争议暂缓 |
| 申请审核 | `settlement_reviewer`，目标用户 | 核对确认来源、本单占用和原收款资料，不审核本人申请 |
| 高额申请复核 | `verifier`，目标用户 | 按原申请规则，另一身份复核后才进入待人工处理 |
| 付款经办、凭证上传 | `manual_handler`，目标用户；凭证上传需有效经办岗位及非空数据范围 | 独占领取，不能接办本人申请；岗位分离开启时不得与申请审核／高额复核相同 |
| 付款登记复核 | `verifier`，目标用户 | 不得复核本人登记；岗位分离启用时不得兼任本单审核或经办 |
| 数字与队列审计 | `auditor`，目标用户 | 只读，不直接改变数字或处理申请；原敏感资料查看仍须对应岗位授权 |

日界为北京时间；申请次数、每日累计及累计申请额包含撤销／驳回的历史提交，草稿页面明确此口径。`second_review_cents=0` 不启用高额复核；`reminder_seconds=0` 不启用提醒。规则未发布时禁止申请，不自行补出正式金额。启用支付宝必须显式填写并批准资料人工检查政策；账户仍非官方验证资料，不采集密码、验证码、证件或接口授权。

## 用户申请与数字核对

1. 使用可信微信登录，完成本人收款二维码上传或支付宝账户资料填写。小程序查看待审、可申请、申请占用、争议暂缓、已登记结算及流水；预计／待审不会增加可申请数字。
2. 填元文本，最多两位小数；客户端精确转整数分，后端再次拒绝负数、超精度／非整数及安全范围外数字。选择原资料编号与版本，先预览并核对原图／脱敏账户、规则及金额，再主动确认。
3. `withdrawal_apply` 在同一事务校验账户、限制、规则、资料归属、汇总版本、有效来源、限额及可申请数字，固定资料与规则快照并追加来源占用。不足／版本冲突不缩额、不产生部分申请；HTTP 错误附 `details.summary` 与 `details.applications`，用户端可刷新查看。
4. 用户更换、停用或修改资料不改变旧申请；待审／待独立复核／待人工处理且没有经办时可撤销。经办已开始后不再直接撤销或释放。
5. 流水使用追加位置高水位游标，新增记录不会让后页重复旧记录；汇总不由翻页累计。数字来源、每单占用或汇总不一致时暂停新增申请并提交关联工单。

## 审核、人工处理与登记

1. Web“提现审核与人工结算”按阶段、时间、标记金额、收款方式查看；超规则时长只显示待办提醒，不自动通过、付款或释放。
2. 审核人记录资料及佣金来源核对声明和原因。通过仅进入“待人工处理”；按原规则需要高额独立复核时先停在待复核。驳回保留快照，且只释放一次本单占用。批量操作先预览笔数、标记总额及异常条目，确认完全相同的版本清单后逐笔可追踪处理，不生成转账文件。
3. 经办独占领取后，付款由人在系统外执行。交接注明接收人、是否已付款、原因；接收人确认前仍由原经办负责，交接待接收期间不能登记。不要因系统超时再次线下付款。
4. 线下结果不明调用 `settlement_unknown` 转“待核实”，保留全部本单占用。确认未付款且停止处理，才可 `settlement_confirm_unpaid` 结束并释放；已有登记须先关联更正及独立复核。不能按超时推断结果。
5. 登记完整金额、原资料编号确认、线下付款时间、凭证与说明。系统补充操作者及登记时间。金额或凭证不符／部分金额转待核实，不自动拆分结算。真实图片校验与私有用途／归属检查由服务端执行。
6. 若配置需要登记复核，先显示“付款登记待复核”，仍保留占用；独立复核后转换为“已登记结算”，不再重复扣数字。人工凭证不是官方到账证明。
7. 误登记使用 `settlement_correction_propose/review` 保留原登记、依据及独立核查；未结算且明确未付、处理停止后可结束释放。已登记结算后的更正只增加争议及更正记录，不静默回滚结算、不追回或抵扣后续佣金。

敏感快照通过 `withdrawal_receipt_reveal` 携带用途；图片通过已认证文件请求及 reason 查看。仅本人、授权申请审核、当前独占经办及复核人员可看对应快照；普通列表不返回完整账户、姓名、收款图或凭证文件编号。敏感查看及原键重放也记录原因与追踪号。用户异议通过 `correction` 关联本人流水或申请，客服不能直接改数字。

## 接口与重试

公开 URL 保持 `/api/v1/community/read/{section}` 与 `/api/v1/community/commands/{action}`，具名 remote 由实际领域所有。两端仅各 feature `api/index.ts` 引用契约。

- `commissions`：`summary/entries/source/proposals/disputes`；`commission_adjust_propose/review`、`commission_dispute/resolve`。
- `withdrawals`：`rules/mine/queue/detail`；`withdrawal_rule_propose/review`、`withdrawal_preview/apply/cancel/receipt_reveal`。
- `settlements`：`settlement_review/second_review`、`settlement_batch_preview/batch_review`、`settlement_claim/handoff/handoff_accept/unknown/confirm_unpaid/register/verify/correction_propose/correction_review`。
- 状态转换携带申请 `version`；申请携带 `summary_version`、`receipt_id/receipt_version`，最终提交再带 `preview_id` 与 `confirmed`。`amount_cents`、时间和阈值均为整数，币种 CNY。
- 每次确认使用稳定 `Idempotency-Key`；未知结果先 `platform.commandResult(key)`，未发现时以原动作／内容／键重试，不能产生另一份有效登记或再次付款。同键不同内容返回 `IDEMPOTENCY_CONFLICT`。
- 主要业务错误：`RULE_NOT_CONFIGURED`、`VERSION_CONFLICT`、`INSUFFICIENT_AVAILABLE`、`RECEIPT_INVALID`、`PREVIEW_REQUIRED`、`BUSINESS_CONFLICT`、`FORBIDDEN`、`SERVICE_UNAVAILABLE`，保留可读说明及追踪号。

## 自动化验证

环境：2026-10-28，Linux；Rust 1.97.1，Node 22.17.0、pnpm 10.12.4（本机实际版本；项目声明 11.22.0），隔离嵌入式 PostgreSQL 17。执行及最终结果见下表；所有测试门槛是夹具，非已确认业务规则。

```bash
make check-web
devbox run -- make check-backend
devbox run -- make test-business
pnpm --dir frontend/apps/web exec playwright test
```

`test-business` 只启动一次性本地 `crowd_test_embedded`，强制覆盖外部数据库环境变量，执行原综合用例与新增 `finance_postgres`；绝不回退到生产连接。数据库用例包含实际 PostgreSQL 触发器抛错注入、按用户范围授权的经办上传与登记，验证失败后申请版本、流水与幂等结果原子恢复。测试结束销毁临时库。

| 检查 | 最终执行结果 |
| --- | --- |
| `make check-web` | 通过：契约类型及运行时契约测试、React／uni-app 类型、ESLint、Web 与微信小程序构建；共用 Rust 佣金汇总 JSON 及全部新命令原键验证。 |
| `devbox run -- make check-backend` | 通过：fmt、check、全 target Clippy（拒绝警告）、70 项测试；其中新增佣金／提现／结算领域15项。默认忽略的2项数据库用例单独执行。 |
