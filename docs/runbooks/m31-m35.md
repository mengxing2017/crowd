# 四方案交付验证与端到端清单

需求和实现见[状态、实体及能力追踪](/requirements/m31-m35)。原始依据为 report/31、32、33、35；以下自动化是隔离业务模拟，不涉及真实付款或官方到账验证。

## 运行与证据

```bash
make delivery-validate
devbox run -- make check-delivery
```

统一入口先校验32个编号和对应测试函数，再顺序执行 `make check-web`、`make check-backend`、`make test-business`、`make docs-build`。使用临时PostgreSQL17和隔离数据库，绝不回退到生产URL。任何检查失败即停止，并记录已执行项与未执行项。JSON证据默认写 `/tmp/crowd-delivery-*`，命令退出时输出路径；不记录环境变量或敏感接口载荷。可使用 `python3 tools/check_delivery.py --output-dir /tmp/指定目录` 留存证据。

## 人工验收记录模板与发布检查

每项按 report/35 前置条件执行并保留：环境／构建版本、测试账号岗位和范围、申请／任务／登记编号、请求追踪号和原幂等键、脱敏截图、执行人／复核人、时间、结果及遗留问题。线下动作由人工演练记录，不能用接口成功代替实际付款。

发布前核对迁移0011已执行、旧小程序兼容、独立岗位和数据范围、私有存储与下载拒绝越权、原结果查询、未结占用和规则快照。数据库约束新增后不回滚删除迁移；代码回退也须保留追加历史和新字段，旧版本不得改写历史。没有支付网关、自动付款、支付查单、超时推断或付款重试。

真机验证：弱网提交后查询原结果、重复点击、前后台切换、私有图片授权失败、辅助功能文字状态；支付宝页面不得出现支付密码、验证码或接口授权。恢复演练：线下已付但登记未写入时，先查原结果再用同一请求键登记原快照，核对paid_at和recorded_at，不再次付款。
