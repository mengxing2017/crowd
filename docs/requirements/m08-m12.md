# M08–M12 实现与验收追踪

后续衔接：M13–M16 已接入佣金数字、提现申请和人工结算；本文原实施时点的 `pending_ledger` 及未接入说明为历史记录，当前行为以 [M13–M16 运行记录](../runbooks/m13-m16.md) 为准。
本阶段需求范围为 M08 佣金定价与规则版本、M09 任务模板与参与资格、M10 任务领取与执行状态、M11 任务证据与成果提交、M12 任务审核与质量判定。以下业务参数与 50 条逐项追踪记录说明需求、实现及验证边界；代码实现与自动化验证不是业务验收。M13 数字台账、提现申请及人工结算不在本阶段范围。

## 业务参数与依赖

- 金额采用 CNY 安全整数分；固定 1.01 元存为 101 分。比例使用整数分子／分母，显式选择向下、向上或四舍五入，采用 i128 中间运算，再校验安全整数结果。比例方案必须明确可信基数来源，可选单笔封顶；无封顶时显示“按可信成果待核定”，旧式数字字段0仅为兼容占位，不代表零佣金承诺，金额区间筛选不包含此类未核定任务。需要用户周期或活动数字最大预占时必须明确封顶，不能以未知数字计算可用上限。
- 无正式业务金额、期限、名额或复核阈值默认值。配置人员显式填写频次、周期锚点、执行和提交期限、文件限制、退回／超时释放策略、暂停策略、补交次数、审核提醒时限及是否双人复核。工程文件处理上限仍为真实 PNG/JPEG、5 MiB、4096×4096，表单策略可更严格；这些不是业务已确认的资料标准。
- 定价及模板新编号保存为待审版本；拒绝覆盖已有内容。另一名复核人员批准后才可关联产品。定价按任务、结算范围、人群及时间排除重叠；产品明确引用一个定价版本，不在运行时猜测多个人群优先级。需要另一价格时建立新版本并重新审核发布。
- 有经核验标签的人群才可领取该人群的产品版本；不接受自报资格／地区／佣金。产品发布前展示固定批准条件，领取时再次核验资格、规则、频次及剩余名额。产品名额与模板名额共同生效。
- 参与次数按稳定任务编号统计；模板总名额按独立模板版本编号统计。周期起点和长度由运营填写，UTC 整数秒计算，日报可配置长度 86400 秒与明确起点，不隐含业务时区。一次性参与保留终止历史；其他频次是否释放由领取快照确定。
- 周期数字上限按用户及结算范围统计当前周期：固定规则占用应得整数分，有封顶比例规则占用单笔最大值；无封顶且无数字上限时只占名额、数字待核定；审核确认后按实际结果记录数字占用，放弃、失效、最终驳回按快照释放。它们都是运营数字控制，不是资金冻结。已确认佣金结论进入争议不会释放或再确认原数字。
- 原 M05–M07 内嵌模板领取作为历史记录保留，没有独立模板引用的旧记录不会自动生成任务实例或被新规则解释。旧客户端与已发布产品仍可读取、领取旧式快照；要启用执行流程须关联批准的 `template_id` 和 `price_id` 并重新发布。
- 可信成果只通过内部 `VerifiedTaskResult` 端口和服务入口写入，无用户可伪造的 HTTP 成果确认入口。接入方仍需实现来源认证、验签、时效检查，当前没有部署外部适配器。比例审批和外部成果型任务在缺少可信结果时明确阻断。
- 审核通过事务追加唯一佣金确认及数字变更事件，状态为 `pending_ledger`、`withdrawable=false`。M13 未接入前不生成可申请余额，不称为完整佣金入账。争议追加暂缓核查事件，保留原确认；后续台账消费方必须先处理争议再应用确认，不得直接将 outbox 当可提现余额。
