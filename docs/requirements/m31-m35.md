# 状态、实体、页面能力与交付追踪

依据 report/31、32、33、35 四份报告实施；不包含 report/34 的未确认决策固化。依赖 M01–M29 的身份、私有文件、任务快照、数字流水和人工登记。本文记录实现，业务验收须另留人员签字与证据。

## 状态及数字（报告 31）

| 对象 | 当前实现状态 | 约束 |
| --- | --- | --- |
| 产品 | 草稿、审核、计划上架、公开、下架／到期 | 定价及模板通过复核才可发布；无资金到账前提 |
| 任务 | claimed → in_progress → submitted → reviewing → approved／rejected；supplement 和 awaiting_verification 分支 | 原提交版本和审核结论保留；领取固定规则；确认业务键去重 |
| 申请 | pending_review → awaiting_second_review（按规则）→ ready → processing → awaiting_verification（按规则）→ settled | ready 仅待人工处理；无支付动作 |
| 核查 | processing → unknown → 人工核查、补录或确认未付退回 | unknown 保留占用，uncertainty_assignee记录当前经办责任人，不能超时自动释放或推断付款结果 |
| 退回 | 原协议 status=rejected，新增 resolution=returned_unpaid | 必须确认未付款且已停止处理；新界面显示“已退回（确认未付款）”；旧客户端仍可读 |
| 登记后争议 | settled + post_settlement_dispute 或关联 dispute | 原登记不变、不追回、不默认抵扣未来佣金 |

累计确认 C=`gross_confirmed_cents`；净调整 J=`adjustment_cents`；有效占用 O=`held_cents`；争议暂缓 H=`disputed_cents`；已登记 S=`settled_cents`；可申请 A=C+J−O−H−S。为兼容旧客户端，`confirmed_cents` 仍为 C+J。全部整数分、CNY；新字段可选以兼容旧服务端。

1000 确认、600 申请：C=1000/J=0/O=600/S=0/A=400；登记及必要复核后 O=0/S=600/A=400；确认未付停止后 O=0/S=0/A=1000。净调减400：C=1000/J=-400/A=600，原确认记录保留。待审1000不进入C或A。

每单只能有一条原占用；累计释放加登记不超过原占用。即使重复占用与重复释放互相抵销，汇总也标记不一致并拒绝新申请。来源分配、应用总量和逐单占用同时核对。

## 逻辑实体与存储（报告 32）

当前是 PostgreSQL `crowd_state.document` 事务锁定存储及独立身份／文件表，不把逻辑字典宣称为已建二十张关系表。物理拆表和金额阈值不在此次固化范围。

| 逻辑实体 | 当前权威位置／关联键 | 版本及保护 |
| --- | --- | --- |
| user | users；可信身份及 crowd_sessions | profile_version、同意版本、服务端注册时间 |
| promotion_code | codes，owner → users | 个人主码唯一，换发保留历史 |
| product | catalog 产品及发布版本 | 公开版本与草稿隔离 |
| task_template / commission_rule | tasks 模板及定价版本 | 独立复核；任务领取固定快照 |
| task_instance | tasks.instances，id／owner／product_id | 模板、定价及归因快照 |
| evidence_submission | instances.submissions，receipt.id | 不覆盖旧提交 |
| task_review | instances.decisions | 新记录 id=命令编号:任务编号；task_id、submission_id、人员和时间；批量任务不共用一个审核编号 |
| commission_marker | tasks.confirmations + commissions.entries | task:实例:受益人:confirmed 业务键 |
| marker_summary | commissions summary 计算读模型 | 流水水位 version，无可直接修改余额 |
| marker_change | commissions.entries | key/id、来源、整数分、操作者、时间；迁移0011数据库追加保护 |
| receipt | users.receipts | 版本化私有图／账户，official_verified=false |
| withdrawal | withdrawals.applications | id、owner、原收款和规则快照、version |
| marker_reservation | withdrawal:{id}:hold／release／settled 流水 | hold业务键为占用逻辑编号；逐单累计校验，无独立资金账户 |
| manual_handling | applications.handling + handler + events | 新领取生成独立id、申请关联、开始人员／时间；交接事件保留双方和已付说明 |
| manual_settlement | applications.registration / correction | 独立登记id、request_id、handling_id、paid_at／recorded_at；更正引用原登记 |
| activity | campaigns | 可选运营数字上限，不是资金预算 |
| task_event | tasks.event_receipts | source/event_id 去重，原始已签名载荷SHA-256摘要、发生／接收时间、验签结果；不存密钥 |
| ticket / audit | support / audit | 用途、对象、动作、追踪号、结果；私有内容不进入通用日志 |

迁移0011只加约束，不回写旧记录：保护数字流水前缀、申请归属／金额／收款／规则快照、原登记核心字段；登记复核元数据可追加。旧审核、经办和事件记录不会伪造新编号或历史摘要。已引用资料仍按既有保留政策处理。

逻辑关系：用户1:N推广码／任务／收款版本／申请；产品1:N任务；任务1:N成果提交及审核；任务确认1:N数字变更；申请1:1有效原占用、1:N释放／结算变更、1:1经办流程及有效原登记；经办流程1:N交接事件；原登记1:N更正提案。每一条来源分配追溯到任务，申请固定收款版本，修改用户当前资料不会沿关系改写旧快照。

## 页面、权限与接口（报告 33）

报告中的 REST 路由是建议；保留已发布接口，由各领域具名 handler/client 承担实际能力。具名调用定义在 `api-contract/src/modules/*/client.ts`，服务端路由在各领域 north/remote。

| 页面／能力 | 岗位及对象范围 | 当前契约入口 |
| --- | --- | --- |
| 登录、本人资料、推广码 | 可信身份／本人，推广归属服务端决定 | identity、promotion |
| 公开产品、我的任务、成果提交 | 公开已发布版本／本人任务 | catalog、tasks |
| 收款资料、私有图片 | 本人版本；受限人员按用途授权 | receipts、files |
| 数字汇总、来源及流水 | 本人；审核／复核／审计须有该用户范围 | commissions |
| 提现预览、申请、撤销、原结果查询 | 本人，版本、规则及原幂等键 | withdrawals、platform |
| 任务审核和规则版本 | 对应审核／复核岗位及产品范围；不得自审 | tasks |
| 人工审核、领取、交接、待核实、登记 | 审核／独占经办／独立复核，申请人不能处理本人单 | settlements |
| 工单、数字修正、争议 | 客服只提工单，数字变更独立申请复核 | support、commissions |
| 统计、内部核对与导出 | operator／auditor及数据范围，下载再次鉴权 | reporting、audit |
| 隐私、注销及权限政策 | 本人申请／独立审批，保护未结业务 | privacy、identity |
| 可选可信任务成果事件 | 原始体HMAC、固定来源、时效及事件去重 | tasks 的 signed event 入口 |

| 报告建议能力 | 当前已发布路由示例（非新增别名） |
| --- | --- |
| GET /me、我的任务 | GET /api/v1/community/read/me；GET /api/v1/community/read/my_tasks |
| 数字汇总及变更 | GET /api/v1/community/read/commission_summary；commission_entries；commission_source（同一read前缀） |
| POST /withdrawals 与撤销 | POST /api/v1/community/commands/withdrawal_preview；withdrawal_apply；withdrawal_cancel（同一commands前缀） |
| 人工领取、交接、核查、登记及复核 | POST /api/v1/community/commands/settlement_claim；settlement_handoff；settlement_unknown；settlement_confirm_unpaid；settlement_register；settlement_verify |
| 超时查原结果 | GET /api/v1/community/read/command_result?target=原请求键；鉴权后返回原结果 |
| 可信任务成果事件 | POST /api/v1/task-events；部署来源凭据验签，与支付回调分开 |
| 私有附件传输 | GET／POST /api/v1/community/files/{id}；获取／上传仍检查用途、归属及授权 |

以上请求的target及动态路径由客户端编码；写命令保留原幂等键和对象版本。领域client通过中立transport适配两端，各端feature/api暴露能力，不在shared存放DTO或client。

所有写命令在共享事务前拒绝客户端提供 `official_verified`、`external_payment`、`payment_verified`、`gateway_response`（包括嵌套）。这是输入边界校验，服务端历史快照仍可返回 false。任务事件严格字段白名单及整数基数校验，不触发付款。

错误保留原 `error.code`、说明和追踪号，新增可选 `business_code`：INSUFFICIENT_AVAILABLE → MARKER_AMOUNT_INSUFFICIENT；RECEIPT_INVALID → RECEIPT_MATERIAL_REQUIRED；其他保持原码。待核实是成功查询到的 unknown 状态，保留占用，不伪造接口失败或官方到账结论。

## 验收与交付（报告 35）

完整32项映射见[交付验收手册](/runbooks/m31-m35)。`tools/delivery_cases.json` 保存案例编号、测试引用及人工验收待办；`make delivery-validate` 检查编号完整和测试引用存在；`devbox run -- make check-delivery` 顺序运行契约／两端、后端、隔离库和文档，输出独立JSON证据。自动化检查只记录套件结果，不将所有端到端业务用例自动标为已签收。
