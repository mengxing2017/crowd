# M20–M24 数字调整、活动统计、消息、客服与风险核查

本阶段实现任务撤销与佣金数字调整、活动额度与统计、消息告知、客服工单与申诉、风控与反作弊五个模块。实施依据为 REQ-20-001 至 REQ-24-010。代码实现和自动化检查不代替业务验收。

## 范围与依赖

依赖已有身份与岗位范围、产品发布、领取快照、证据审核、佣金追加流水、提现占用和人工结算记录。沿用同一 PostgreSQL 事务及原请求键，不修改已发布客户端使用的旧接口。新客户端按 commissions、campaigns、notifications、support、risk 所有权分别接入。

佣金是数字标记；活动额度是可选运营计划。退款、付款和追偿均在系统外，不增加支付调用、自动付款、自动查单、付款重试或真实资金池。通知重试只处理消息发送。

## 需求追踪

### M20 任务撤销与佣金数字调整

实现位于 `backend/src/commissions/domain/adjustments.rs`，跨领域写入由 commissions 的 south 消费端口调用 tasks／withdrawals 提供端口。管理端为“任务撤销与数字调整”，小程序为“数字调整与受限说明”。

| 需求 | 当前实现与验证重点 |
| --- | --- |
| REQ-20-001 撤销依据登记 | 保存来源、唯一依据号、任务、说明及操作身份；同依据不可重复创建 |
| REQ-20-002 原任务定位 | 按任务编号与用户校验；未知任务进入 pending_location，补充可信定位后才可复核，不按昵称批量扣减 |
| REQ-20-003 待审标记取消 | 独立复核后取消待审任务并释放计划占额，不生成已确认数字调减；其他任务确认数不变 |
| REQ-20-004 确认数字调减 | 在原来源新增 decrease 流水，保留原确认和完整调整依据；不足可调整数字时拒绝 |
| REQ-20-005 部分失效计算 | 可信确认基数与原规则舍入方式按整数计算；无可信原基数时不接受比例推算，固定规则使用明确复核数字 |
| REQ-20-006 申请中调整 | 定位原来源占用的申请，保留原占用、经办和收款快照，标记 adjustment_review_required；阻止继续领取经办、登记和复核结算 |
| REQ-20-007 已结算争议 | 保留已登记结算，将调整留在 awaiting_resolution；不追回外部款项，也不从其他来源或未来佣金抵扣 |
| REQ-20-008 调整恢复 | 恢复关联已生效原调减，新增 increase；已申请恢复与已生效恢复合计不得超过原调减 |
| REQ-20-009 用户变化说明 | 本人可查原任务、方向、数字、依据、进度与核查说明；通过关联流水或任务工单提出异议 |
| REQ-20-010 批量调整复核 | 先固定条目与版本，显示影响人数、数字和在途／已登记申请；独立复核逐条重新验证，在同一事务生效 |

已登记结算争议保留人工核查链路；对应数字争议有明确复核结论后，可解除原申请暂停并继续原登记流程，随后记录争议结案，不预设协商追偿、未来抵扣或外部退款流程。原失效依据撤回使用关联恢复单；不能通过改历史记录掩盖调整。

### M21 活动额度与统计管理

实现位于 `backend/src/campaigns/`。活动包含不可随意迁移的产品集合，避免已有领取更换活动后重置占额。真实领取事务结束前验证活动上限，失败回滚领取和幂等结果。

| 需求 | 当前实现与验证重点 |
| --- | --- |
| REQ-21-001 活动统计建立 | 维护活动名称、负责人、产品及计划数字，统计可回溯领取与流水 |
| REQ-21-002 计划额度可选 | enabled=false 时不执行活动数字上限，不要求充值或到账凭证 |
| REQ-21-003 数字额度设置 | 授权、原因、版本校验；上限不能低于已有执行占额与确认数 |
| REQ-21-004 领取数字占额 | 在同一行锁事务计算活动执行中计划数与已确认数，末份并发只允许一份成功 |
| REQ-21-005 佣金确认统计 | 通过后转入真实确认数字统计，比例计算差额不代表系统资金支出 |
| REQ-21-006 结束释放统计 | 放弃、到期、最终驳回及待审撤销不再占活动执行计划数，原领取与事件保留 |
| REQ-21-007 额度不足提示 | 仅启用上限时阻止超额新领取，错误明确为活动规则限制 |
| REQ-21-008 计划额度调整 | 校验双方活动权限、版本和源剩余计划数，原子修改并保存双方原因、前后值 |
| REQ-21-009 活动汇总报表 | 展示领取、通过、执行中、待审、确认、可申请、申请占用与已登记结算；标明业务统计 |
| REQ-21-010 活动归档 | 确认存量责任，固定归档清单，停止新领取；存量任务、申请和历史数字继续保留 |

统计从领取快照与追加数字流水推导，不能通过手工改汇总纠错。活动产品集合创建后不可覆盖；跨活动产品迁移如需支持须另行设计存量归属规则。

### M22 消息通知与用户告知

实现位于 `backend/src/notifications/`。站内消息在成功业务事务中生成，按事件、模板版本和接收人去重。查询同时返回当前业务状态，不将历史通知当作最新承诺。

| 需求 | 当前实现与验证重点 |
| --- | --- |
| REQ-22-001 站内消息中心 | 任务、佣金、提现、工单及风险消息关联真实编号；本人查询和已读校验归属 |
| REQ-22-002 订阅授权管理 | 按本人、模板与场景保存主动授权结果及版本；未授权不影响站内消息 |
| REQ-22-003 任务临期提醒 | 使用显式发布的 reminder_seconds；只对尚在执行且未到期任务生成去重提醒 |
| REQ-22-004 审核结果通知 | 不同审核状态与原因随任务版本通知，当前状态另行查询 |
| REQ-22-005 佣金数字变化通知 | 确认、调减、恢复及争议暂缓／解除分别关联流水；保留非真实资金说明 |
| REQ-22-006 人工结算进度通知 | 关联提现申请版本；文案明确人工处理、待核实、已登记结算与异议入口 |
| REQ-22-007 后台待办提醒 | 按岗位和对象范围提供待审、人工处理及异常待办，不附收款资料与付款凭证 |
| REQ-22-008 消息去重合并 | 稳定事件与模板版本键保证重复同步不会生成相同通知；不默认合并不同关键业务事件 |
| REQ-22-009 通知失败重试 | 可接入 NotificationDelivery 提供端口；先持久化尝试，再在事务外调用，区分未授权、临时失败、永久失败和次数耗尽，保留站内结果 |
| REQ-22-010 模板版本管理 | 保存模板及历史版本，核对变量、受控目标和预览确认；不得删除编号、状态及数字边界说明 |

仓库没有配置微信订阅发送凭据或启用外部发送任务。模板仅在显式配置正整数 max_attempts／retry_seconds 后可供发送服务使用；接入方须实现稳定消息键去重。发送失败不回滚已经完成的任务、记账或人工登记。30 秒调用超时是服务资源保护，不是业务处理期限或付款结果推断。

### M23 客服工单与申诉

实现位于 `backend/src/support/domain/tickets.rs`。沿用旧资料纠错、注销、身份核验申请入口，不将这些申请与正式工单混为一种状态机。

| 需求 | 当前实现与验证重点 |
| --- | --- |
| REQ-23-001 工单分类提交 | 注册、推广、任务、佣金、提现、审核申诉与风险咨询；小程序可选本人的关联单据 |
| REQ-23-002 关联业务校验 | 服务端校验任务、数字记录、提现和风险单归属，不返回他人详情 |
| REQ-23-003 审核驳回申诉 | 仅对本人驳回任务，依据已发布次数与期限政策；保存新证据说明，不直接生成可申请数字 |
| REQ-23-004 申诉独立复核 | 固定原审核人及政策快照；配置强制独立时原审核人不能结案 |
| REQ-23-005 人工结算异常咨询 | 关联原申请与回复；保留待核实状态，不将客服说明作为到账证明 |
| REQ-23-006 工单流转升级 | 保存队列、责任人、处理截止时间、原因和完整事件，支持转派／升级／退回 |
| REQ-23-007 客服回复与附件 | 用户可见回复与内部备注隔离；附件校验上传人、用途，敏感下载再次校验工单可见性并留痕 |
| REQ-23-008 结案与重新打开 | 当前责任人说明结案，禁止经办结案本人咨询；本人按快照政策重开，保留全部历史 |
| REQ-23-009 申诉数字修复 | 工单结案可关联同一用户正式调整单；数字调整可记录关联工单，不直接改汇总 |
| REQ-23-010 服务质量统计 | 授权范围内统计响应／解决时长与结案集合，保留可回溯编号，不返回收款原文 |

申诉次数、期限和重开期限未预设正式默认值。规则管理员须显式发布；未配置时普通咨询仍可提交，期限型审核申诉与重开提示政策未配置。附件仅支持经真实解码的 PNG／JPEG；5 MiB、4096 像素边长及每次回复最多 10 个附件是当前工程资源上限，不是已确认业务资料政策。

### M24 风控与反作弊

实现位于 `backend/src/risk/`。仅启用显式发布且处于生效时间内的规则，保留规则快照与命中依据；不默认采集设备指纹、通讯录、身份证或额外平台凭据。

| 需求 | 当前实现与验证重点 |
| --- | --- |
| REQ-24-001 重复成果识别 | 沿用任务订单业务键去重；可配置重复证据特征核查，命中生成核查单而非永久封禁 |
| REQ-24-002 异常领取频率 | 对服务器已成功领取记录执行已发布窗口／阈值，拦截新超频请求，不更改已成功任务 |
| REQ-24-003 异常推广访问 | 访问频率信号进入观察；不因访问异常自动抹除合法佣金或直接限制全部业务 |
| REQ-24-004 账号关联核查 | 必要业务目的与已授权信号由风险人员登记人工核查，不以单一相同网络直接封禁 |
| REQ-24-005 收款资料共享 | 规范化支付宝账户与微信码图内容摘要仅在服务端比对；核查单不包含原始资料或公开地址 |
| REQ-24-006 提现异常识别 | 显式频率规则与申请收款快照变化产生核查信号，人工决定具体新申请限制并通知用户 |
| REQ-24-007 风险规则版本 | 记录目的、阈值、时效和样本评估，更新保留历史；命中单固定原规则版本与快照 |
| REQ-24-008 风险名单管理 | 单笔处置限定 owner、scope、expires_at 及复核说明，超过有效期不继续阻止新操作 |
| REQ-24-009 处置分级 | 观察、人工审查、指定领取／申请限制、特定来源数字暂缓分开；数字暂缓另需既有数字审核岗位，不允许低级访问／单一关联信号直接暂缓 |
| REQ-24-010 误判解除 | 保留解除依据与原风险单；数字暂缓解除另需数字复核岗位，额外补记另走正式调整，不自动付款 |

历史微信收款图若尚无服务端内容摘要，不宣称已完成全量重复图片识别；新上传码图保存内容摘要。账号关联只支持明确授权的业务信号人工登记，不实现自动跨平台身份画像。

## 接口、持久化与验证

新查询与命令继续使用统一信封和 `/api/v1/community/read/…`、`/api/v1/community/commands/…` 兼容路径；URL 中的历史名称不代表重新聚合领域。详细接口见 [API 契约](../reference/api-contract.md)，岗位操作见[运行手册](../runbooks/m20-m24.md)。

State 新增 campaigns、notifications、risk，Commissions 新增 adjustments，均带反序列化默认值，旧文档可读取。`0007_support_attachments.sql` 为 forward-only，用于新增 support_attachment 文件用途，不删除历史数据。消息、工单、风险、活动与数字变更在同一 PostgreSQL 行锁事务保存，业务失败恢复原状态；通知外发单独提交，不持有业务锁等待网络。

回归入口为 `backend/tests/operations_domain.rs`、`backend/tests/operations_postgres.rs` 和 `api-contract/tests/community.mjs`。覆盖正反向、权限、版本、重复依据、恢复上限、原收款快照不变、在途／已登记争议、并发活动末份额度、写入失败回滚、原请求重试、消息去重与通知重试上限。共享序列化投影位于 `api-contract/fixtures/operations.json`。

浏览器交互、微信开发者工具、微信真机及外部订阅真实渠道验收需另行实际执行，不能由编译、夹具或模拟渠道结果替代。
