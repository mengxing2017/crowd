# M13–M16 实现与验证追踪

本阶段需求范围为 M13 佣金数字记录与变更流水、M14 佣金汇总与申请占用、M15 提现规则与申请、M16 提现审核与人工结算。以下 40 条追踪记录列出需求、实现落点及核对依据，代码及自动化结果不等同业务验收。业务金额、资料政策及复核阈值需授权人员显式配置并独立批准；没有默认正式门槛。实现决策见 [ADR 0011](../adr/0011-commission-withdrawal-manual-settlement.md)，配置及实际验证见 [运行记录](../runbooks/m13-m16.md)。

后端按 `commissions`、`withdrawals`、`settlements` 分域，沿用锁内事务、原请求键、审计及失败恢复；契约包及两端使用同名领域入口。依赖 M03 私有收款资料、M08 价格快照／整数计算、M10–12 任务提交和审核确认、身份岗位及数据范围。不调用支付接口，没有真实资金池。

## 验证边界

- `backend/tests/finance_domain.rs` 验证数字、来源、状态、角色、争议、快照、调整和分页；`finance_postgres.rs` 在一次性库验证两个600分申请竞争1000分、原键重放、撤销与经办竞争、凭证越权、真实 PostgreSQL 写入异常回滚及原键恢复。
- 任务已有回归覆盖固定／比例计算、补交、重复确认、独立审核及撤销后争议衔接；旧确认记录不重写，后续新确认通过唯一键进入数字记录。
- `api-contract/fixtures/commission-summary.json` 同时由 Rust 序列化与 TypeScript 运行时校验；契约命令表检查三领域全部命令与原键。Web 浏览器使用模拟接口核对表单、岗位入口及登记超时重试，不能代替真实后端或付款验收。
- 正式规则配置、业务人员签收、微信真机与真实线下凭证流程尚未验收；无官方到账验证。
