# M17–M19 收款资料与人工登记追踪

本阶段覆盖微信收款二维码管理、支付宝收款账户管理、人工付款登记与异常处理，共 30 条需求。复用 M03 和 M13–M16 的私有文件、申请快照、数字占用与登记复核，补齐声明版本、支付宝格式政策、默认资料展示、保留策略清理及异常分类。代码实现与自动化结果不等同业务验收。

## 规则与依赖边界

- 微信仅上传本人收款码；支付宝仅填写账户及按明确政策要求的姓名。没有支付密码、验证码、身份证追加采集或官方账户验证接口。
- 资料保存记录 `receipt-self-v1` 本人声明和服务端确认时间。微信确认后可用；支付宝必须有独立发布的格式、姓名政策，否则仅保存草稿。已存在草稿不能因新政策发布自动变为可用，需用户重新确认生成版本。
- 格式政策显式选择 11 位、以 1 开头的纯数字手机号或基本邮箱语法；仅本地格式检查，不证明账户存在或可收款。规则发布不能替代业务人员对适用政策的确认。
- 默认资料由每种方式最新的、未停用的已确认版本推导，历史资料不改写；旧申请始终引用原快照，并记录申请确认时间。停用不删除旧申请资料，也不改付新账户。
- 保留期限没有正式默认值。只有显式配置并独立发布 `receipt_retention_seconds` 和策略依据后，本人可申请清理已停用且无任何申请、其他资料或核查保全引用的微信图。当前按文件上传时间计算文件年龄；任何历史申请引用均保留，即使申请结束。工程未实现自动清理调度，不推断争议保全到期。
- 异常分为资料错误、尚未付款、结果不明、登记错误；须由独占经办分类并指定有本单数据范围的经办责任人。责任指派不替代双向经办交接，不释放占用。资料／登记错误不可降级绕过处理；资料错误需核实未付后退回重提，登记错误走关联更正。
- 异常后登记原线下结果须主动确认已核查；结果不明不自动查单、释放、重试付款或补付。登记及独立复核符合规则后才结转数字；已登记结算更正不意味着外部退款或追回。
- 沿用共享状态 PostgreSQL 事务行锁与幂等记录，无新增数据库结构迁移。旧客户端路径继续兼容；旧规则缺少支付宝格式政策时不得把草稿作为可申请资料。

## 逐项追踪

| 需求 | 规则与核对点 | 实现入口 |
| --- | --- | --- |
| REQ-17-001 微信收款码上传 | 用户从相册选择或拍摄本人微信收款二维码图片，仅上传文件不连接微信支付。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-002 图片格式校验 | 检查文件真实格式、大小、清晰度提示和允许类型，限制值待确认。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-003 码图人工可读 | 上传后可预览缩放并提示无遮挡，是否可收款只能由用户和线下经办核实。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-004 本人收款声明 | 提交前让用户确认该码可供本人收款且资料正确，记录确认版本。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-005 码图私有存储 | 图片使用私有访问权限，不发布为任何人可访问的长期链接。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-006 默认码与换图 | 可更新默认收款码，新版本只用于后续新申请。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-007 申请码图快照 | 申请引用当时码图不可变版本，必要保留只读快照直到处理和争议结束。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-008 经办查看码图 | 仅处理该申请的授权经办可查看和按需要下载，下载记录用途与操作者。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-009 错误码资料处理 | 码图过期、模糊或收款对象疑问时暂停人工处理并要求重新申请或受控更正。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-17-010 保存与到期清理 | 按已确认的保留策略清理无引用旧图，争议保全和必要历史快照除外。 | `receipts`／`files`；小程序个人中心、Web 申请详情 |
| REQ-18-001 收款账户填写 | 用户提供支付宝收款账户，可按业务约定支持手机号或邮箱形态，不采集密码及验证码。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-002 账户格式检查 | 只校验格式、长度及基本完整性，不把本地格式检查称为官方账户存在性验证。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-003 收款姓名信息 | 是否需要收款姓名由平台业务确认，未确认前不额外索取身份证件。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-004 提交资料确认 | 用户确认支付宝账户及必要姓名无误后保存版本。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-005 账户安全保存 | 账户原文受控保存，列表和用户确认页面默认合理脱敏。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-006 账户修改版本 | 用户修改账户生成新资料版本，不原地覆盖历史申请快照。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-007 申请账户快照 | 提现申请保存独立的账户版本及用户确认时间，线下付款以此为依据。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-008 经办查看与复制 | 授权经办在处理具体申请时可查看或复制完整账户，操作留痕并避免日志泄露。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-009 账户错误处置 | 格式看似正确但经办发现不可用时登记问题并核查，确认未付款后退回或重提。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-18-010 账户解绑保留 | 停用仅停止新申请使用，历史申请所需快照按保留策略受限保存。 | `receipts`／`withdrawals`；小程序个人中心、Web 规则及申请详情 |
| REQ-19-001 人工处理状态 | 系统只记录待人工处理、处理中、待核实、已登记结算等状态，不维护支付网关状态机。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-002 领取处理单 | 经办领取后显示固定收款快照和申请标记金额，明确需要在系统外手动付款。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-003 处理重复保护 | 申请处理锁与版本防止两人重复操作，页面提醒先核查是否已线下支付。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-004 线下结果待核实 | 经办不确定线下结果时登记待核实并保留本单数字占用，由人员在外部核查。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-005 登记付款凭证 | 经办完成外部手动付款后上传凭证并填写时间、参考金额、方式及必要流水备注。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-006 处理异常分类 | 区分资料错误、尚未付款、线下付款不明和登记错误，分别指派人工处理。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-007 结果复核 | 按规则由授权人员核对凭证与申请快照，未满足复核条件不结束申请占用。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-008 结算数字结转 | 有效人工登记及必要复核完成后将本单占用数字转为已登记结算，明确非官方到账验证。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-009 未付退回释放 | 经办确认未线下支付且不会继续处理后可退回，记录依据并释放原占用。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |
| REQ-19-010 误登记更正 | 已登记结果错误走独立更正流程，保留原凭证和原因，并核查是否实际已付。 | `settlements`／`withdrawals`／`commissions`；Web 人工处理台 |

## 验证依据

- `backend/tests/receipt_management.rs`：显式账户政策、草稿禁用、姓名规则、格式反例、声明序列化、并发版本拒绝、资料归属和快照。
- `backend/tests/finance_domain.rs`：分类责任人权限、占用保留、错误资料阻断登记、原经办确认未付释放；既有登记／复核／更正与争议回归。
- `backend/tests/finance_postgres.rs`：真实事务中政策发布、脱敏、历史引用保护、无引用图清理、保留期内拒绝、越权和同键重放，以及数据库写入失败时二进制删除回滚及原键恢复；沿用并发占用及登记故障回滚。
- `api-contract/fixtures/receipt-confirmed.json`：Rust 生成资料记录与 TypeScript 响应校验共享样本；契约测试核对新命令所属领域、原键及旧接口兼容。
- `frontend/apps/web/tests/finance.spec.ts`：规则配置、异常分类责任人、岗位隔离、登记超时原请求重试。浏览器使用模拟接口，不代表真实线下付款验收。

操作、实际执行结果和未验证项见 [运行手册](../runbooks/m17-m19.md)，架构决策见 [ADR 0012](../adr/0012-receipt-management-manual-exceptions.md)。
