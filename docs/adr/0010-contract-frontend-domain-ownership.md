# ADR 0010：契约与两端前端同步领域归属

## 范围与依据

根据用户要求，将 ADR 0009 已完成的后端职责拆分同步到 `api-contract`、React 管理端和 uni-app 用户端。本次不修改后端、数据库迁移、HTTP 地址或业务规则。验收要求是独立客户端只暴露其所属能力，两端不依赖混合 community feature，原登录、权限展示、提交防重、原结果查询及原键重试行为保留。

## 契约组织

新增 `receipts`、`promotion`、`audit`、`support`、`files`、`platform` 子路径导出；调整原身份、归因、任务和规则客户端的职责。完整调用迁移映射见 [契约说明](../../api-contract/README.md)。`User.receipts` 是接口中的跨领域快照，类型显式引用收款领域，收款业务方法不再由身份客户端暴露。

`common` 保持无业务依赖，统一 JSON 与二进制上传响应的信封／业务错误识别。文件契约只提供编码路径、上传结果类型及解码器，不依赖 DOM 或平台运行时。推广二维码路径属于推广领域。收款、推广、审计和客服的独立客户端及兼容通用入口执行相应响应校验。

所有契约 `index.ts` 只导出，包括原技术性 system 入口。`community` 保留原类型、`BusinessError`、`taskStatusNames`、通用读写和登录／协议／目录／触点／推广解析方法，作为旧调用的兼容门面；各独立领域不依赖它。

## 前端组织与一致性

- Web 登录与用户管理归 `identity`，收款接口归 `receipts`，规则中心归 `governance`，推广管理和落地页归 `promotion`，审计页归 `audit`，目录与任务页归原领域。用户页中的地区／资格编辑组件由 `tasks/Eligibility.tsx` 提供。`workspace` 仅组装导航、登录恢复、页面与通用提交交互。
- 两端删除 `features/community/api`。小程序路由页通过各领域 API 组装个人中心，任务执行组件使用自身任务类型及独立文件 API。前端 DTO/client 不迁入 shared。
- 每个 feature 的 `api/index.ts` 实例化其所属客户端并导出显式命令表。`platform/commands.ts` 组合这些表，使用对应客户端方法提交；未知动作拒绝，不转发到任意动作通用入口。结果查询使用 `platform.commandResult`。
- 共享端内 session transport 保留 Bearer 头、幂等键、无缓存策略和原会话存储／恢复逻辑。待确认提交继续固定 owner、原动作、原内容和原请求键；不因结果查询创建第二份命令，不因类型迁移清除待确认状态。
- 各端 `files/api/index.ts` 负责原生文件读取、二进制上传及授权下载；上传使用契约信封解码和业务错误，证据读取继续传递用途。服务端仍负责权限、资源归属及实际文件验证。
- TypeScript 和 Vite 继续解析本地契约源码；Web 排除新增模块的旧预构建副本，避免只更新源码后运行时遗漏新入口。

## 验证

```bash
make check-web
pnpm --dir frontend/apps/web test:e2e
```

契约测试覆盖所有子路径入口仅导出、依赖方向、跨语言历史序列化样本、新领域方法的路径／请求键／错误类、错误响应拒绝、文件用途及原因编码和原提交结果查询。两端源码边界检查及 Lint 禁止兼容领域依赖和在 feature API 入口之外直接导入契约。

浏览器回归覆盖原登录、刷新恢复、有限岗位、规则／产品／推广／任务操作和原键重试；新增不确定提交的原结果查询，以及任务资格组件按核验版本提交的验证。浏览器使用隔离的模拟接口，不能代替真实后端联调或微信真机验证。

2026-10-28 实际验证：Linux 开发环境，Node 22.17.0、pnpm 10.12.4。最终 `make check-web` 全部通过，包含契约编译／回归、Web 与小程序类型检查、Lint、Web 构建和微信小程序构建。完整 Chromium 回归中 20 项通过，新增资格编辑场景暴露按钮定位及隐藏表单同名字段的标签关联问题；修正定位、为任务资格表单设置独立名称后，该场景定向复跑通过（1 项）。合计 21 个场景已验证，未将定向复验描述为再次执行整套测试。`git diff --check` 通过。

未执行真实后端联调或微信真机验证。独立领域仓储、真实微信身份和人工线下结算仍遵循既有范围及未验证边界，不因前端构建通过视为业务验收完成。
