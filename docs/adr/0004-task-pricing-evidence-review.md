# ADR 0004：任务快照、私有证据与审核数字确认

状态：已实现，业务验收另行记录。适用 M08–M12，继续采用 ADR 0003 的事务聚合方式。

## 决策

新增 `tasks` 领域模块，定价与模板版本独立存储，产品引用批准版本；领取事务复制模板、定价、资格及名额／数字占用快照。旧式内嵌模板保留原样，不根据后来配置反向推断其状态。产品发布要求显示数字、完成条件、时限与批准版本一致，比例佣金显示计算方式及可选封顶，无封顶时明确数字待核定。

任务执行、证据草稿、精确预览、不可覆盖的提交版本、审核独占、补交、独立复核及更正分别记录。动作同时校验岗位、产品范围、归属、对象版本和状态；服务层先授权，再进行绑定动作及输入的幂等重放。事务失败恢复内存聚合并提交失败审计，不保留半个批量审核结果。

继续使用 `crowd_state SELECT ... FOR UPDATE` 作为一致性边界，JSON 中保存 `tasks`；附件内容在 `crowd_files`，任务附件关联在聚合内，绑定领取实例及上传者。上传与关联、草稿清理与私有文件删除在同一事务内。清理只删除未被历史提交引用的本任务证据，历史证据不会被覆盖。排队、详情和审核动作默认结果均隐藏草稿、预览及证据载荷，查看需独立动作和用途；附件下载再次执行相同边界。

审核通过在同一事务创建按实例唯一的 `pending_ledger` 佣金确认与追加变更事件，并保存完整计算解释。它是 M13 的输入接口，不是可申请余额或外部付款。后续消费者必须以实例与事件键幂等、同时处理争议暂缓并更新自己的汇总，不可只挑确认事件发放数字。争议更正保留原确认，追加关联事件，禁止自动追回或从未来佣金抵扣。

可信成果的内部端口与服务入口隔离于 HTTP。比例基数不能来自客户端上传的订单金额。生产来源适配器必须自行认证、验签、去重及限制时效；没有适配器时相关审核明确失败，不模拟成功事件。

## 代价与限制

全局行锁使额度、重复订单、撤回与审核领取、批量审核等竞争可以在当前阶段确定串行顺序，但并不适合高吞吐。聚合增长包含证据元数据、幂等记录和审计历史；未来拆分表须保留原业务键、快照、版本及事务边界，不删除历史或改变已经发布的客户端协议。当前尚未进行规模／性能验收。

原报告未确认的业务阈值由显式配置表达，不填入默认正式值。配置的有效性检查与工程资源上限不能描述成业务已确认规则。前端编译、模拟浏览器及隔离数据库测试不代替微信真机、生产成果来源或人工业务验收。
