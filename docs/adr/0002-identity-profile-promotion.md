# M01–M04 实现决策

日期：2026-10-27。需求依据为 report/01、02、03、04；用户本次授权连续编码四个方案及更新文档。实现与自动测试不构成业务验收。

## 分层与持久化

`backend/src/community/domain.rs` 管理规则版本、权限与对象范围、资料版本、推广码及申请状态；不依赖 Axum、SQLx。`north/local.rs` 编排身份端口、事务、幂等与文件授权；`north/remote.rs` 只处理 HTTP、提取参数和序列化。`south/port` 隔离微信身份，`south/adapter/wechat.rs` 实现临时 code 交换；PostgreSQL 适配器承载 SQL 和私有图片字节。

初期将 M01–M04 的业务聚合保存为 `crowd_state.document`，锁定单例行后执行用例，和审计、幂等结果同事务提交。平台身份唯一索引位于 `crowd_identities`，码值及每用户每目标的有效码唯一索引位于 `crowd_code_ownership`；会话、一次性票据、私有图片单独存表。此设计优先保证初始跨模块原子性，所有业务写入会串行，整份聚合的读写成本随历史增长；**不是高并发或无限历史规模的最终存储设计**。上线容量目标尚未确认，不据此承诺吞吐。后续拆表须 forward-only 保留旧版本、来源、审计和幂等结果，不能删除历史记录回退。

业务 HTTP 无删除审计或直接编辑汇总入口。数据库运维权限不等同普通管理端权限；生产数据库角色和备份访问仍需部署侧隔离。当前图片保存在数据库私有表，不使用公开 URL 或外部存储凭据。

## 身份与后台登录

生产 HTTP 只能调用微信身份适配器，客户端不能指定 openid、用户编号或角色；测试身份仅通过 Rust 测试注入端口。服务端会话使用数据库随机数，数据库只保存 SHA-256 摘要和期限。会话当前默认 7200 秒，可由 `CROWD_SESSION_SECONDS` 设置，是部署参数而非已确认的业务期限。

小程序登录后可申请 60 秒一次性后台票据，后台兑换为独立会话；数据库原子删除票据，不能再次兑换。票据失效与会话过期均要求重新登录。两端只将凭据和私有响应保存在内存；退出清理界面敏感状态，并撤销当前服务端会话。其他设备会话不会被当前设备退出自动撤销。

原微信初始化路径在空环境仅允许 `CROWD_BOOTSTRAP_PLATFORM_ID` 精确匹配的可信微信身份建立首个管理员，用于发布协议和配置权限。此运维建档例外保留 bootstrap 标记，不能作为普通用户绕过主动同意的通道。管理员初始化后移除此环境变量。授权角色按动作区分，数据范围为用户编号、platform 或显式 `*`；没有“管理员自动拥有全部权限”的逻辑。

微信登录参考：[微信 code2Session 官方接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/user-login/api_code2session.html)。未调用支付、转账、查单或账单接口。

## M01 产品任务目录与边界

M01 的 `product_tasks` 已发布版本作为首期受控目录，记录真实配置的产品编号、任务编号、启停状态、完成口径和证据要求。目录未发布、编号不存在、任务不属该产品或资源停用时，定向码创建和公开解析均拒绝。更新目录须发布新版本，历史版本保留。该目录只提供关联和目标可用性，不代替完整产品展示、任务领取、成果审核或佣金模块，不能据此产生佣金。

规则有草稿、发布、停用；同类型发布会停用上一有效版本。发布数字边界要求 `manual_only: true`，其他规则内容不能开启支付能力。金额展示、完成证据、审核口径、归因和首期变更范围由规则版本表达，尚未实现的下游模块不能被描述为已验收。未确定阈值和策略不预置为正式规则。

## 收款资料、推广与关联申请

收款资料追加不可覆盖的版本；停用追加事件，不改变原版本。普通资料查询脱敏，完整查看需要本人用途说明并记录审计。后台完整资料查看因缺少申请授权上下文而拒绝，不赋予客服跨用户读取能力。头像与收款图片的用途和归属在保存引用时再次核验。图片必须实际解码为 PNG/JPEG；5 MiB、4096 边长和 64 MiB 解码上限仅为当前服务资源边界，待正式资料策略确认。

支付宝账户当前以草稿保存，姓名可不填，不声称支持已验证的手机号/邮箱形式或真实账户验证。手机号绑定默认不启用，拒绝客户端直接提供未经可信凭证验证的手机号。纠错、合并和注销保存申请及理由；纠错进入待人工核实，合并/注销进入待关联业务核查，不自动修改在途申请、不删除历史、不静默合并身份或佣金。关联任务、提现及争议服务尚未接入，不能完成核查或宣称账号清理成功。

注册事务持久化用户、可信身份与推广码生成任务，随后立即尝试生成主码；失败保留 pending 任务。独立后台 worker 每 30 秒重试待生成任务（每批最多 32 个，是工程调度参数，不涉及付款）。用户也可显式幂等恢复。生成与历史码归属、唯一索引、审计在同一事务提交，多实例或并发重试只能产生一个有效主码。推广码为随机不透明标识，与收款码独立；换发保留原码和历史注册来源。换发操作由服务端授权的推广管理人员执行，记录可信操作者、审批依据引用和原因，岗位分离策略尚未确认为正式规则。

二维码编码配置的 HTTPS Web 入口及不透明码，不包含用户编号、手机号或收款账户。Web 落地页解析后允许复制码，在小程序填写来源；不是微信官方小程序码，不宣称能直接拉起小程序。是否启用官方小程序码/URL Link 另按配置和范围推进。

## 2026-10-27：独立管理员登录

Web 默认提供账号密码登录页，保留小程序一次性票据切换入口。参考 `../wekeeper` 的独立账号、Argon2id 与本地管理员初始化方式；账号映射到既有用户权限模型，服务端没有新增超级管理员绕过授权。`crowd_staff_accounts` 单独保存账号及盐化哈希，登录签发既有 Bearer 会话。密码计算在 blocking worker 执行，失败次数与会话/审计在真实 PostgreSQL 事务中处理。

开发嵌入式 PG 自动初始化临时 `admin`，随机密码写入数据目录内 `0600` 文件；按用户明确要求，开发控制台额外显示默认用户名和本次随机临时密码；结构化业务日志仅给出文件路径，退出随数据目录清理。正式 API 不输出凭据。可用 `CROWD_DEV_ADMIN_PASSWORD` 指定本次开发密码。外置库只有同时显式配置 bootstrap 账号和密码才建档，不覆盖既有密码/岗位，创建后移除配置。普通微信用户仍须可信凭证和协议同意。
