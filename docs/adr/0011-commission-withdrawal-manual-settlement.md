# ADR 0011：佣金数字、提现申请与人工结算

日期：2026-10-28。需求依据：[M13–M16 需求追踪](../requirements/m13-m16.md)，涵盖佣金数字流水、汇总占用、提现申请及人工审核结算。状态：已实施，业务规则的正式配置与业务验收另行进行。

将职责分为 `commissions`（待审／确认、不可覆盖流水、来源分配、独立复核调整、争议）、`withdrawals`（版本化规则、预览确认、收款快照、申请／撤销）和 `settlements`（申请审核、独占经办、双向交接、结果待核实、付款登记与独立复核）。`community` 继续仅兼容导出，公开旧 URL 不变。模块入口只导出，HTTP 每个用例独立文件；契约及两端 feature 采用相同归属。

沿用 `crowd_state` 的 PostgreSQL `FOR UPDATE` 事务：授权先于幂等重放；成功提交同时保存申请、原资料与规则快照、数字变更、审计和幂等结果。领域异常还原业务快照，持久化失败则整笔数据库事务回滚。没有另建可人工编辑的汇总表：汇总由整数分流水及任务状态推导，因此没有“只写汇总成功”的第二写入窗口。各申请保存来源分配，来源数字、总汇总及每单占用均核对；异常暂停新增申请，不虚构外部资金对账。

数字使用 CNY 安全整数分，i128 中间汇总。确认来源沿用任务领取时的规则及可信计算输入；任务、受益人、类型构成唯一键，旧 `pending_ledger` 记录在锁内按同样的键衔接，原确认快照不被删除。新确认标注 `confirmed`，`withdrawable` 表示进入平台可申请数字计算，不代表已付款或最终申请资格；客户端仍以最新汇总、限制和规则校验结果为准。

申请占用分配到具体佣金来源。撤销／驳回只释放本单未结算占用；结算将占用转换为登记结算，原来源继续扣除，不再扣第二次。争议仅暂缓对应来源的可用部分；申请释放时仍有争议的来源部分转为争议暂缓，不重新暴露为可申请数字；已占用部分阻止关联单继续结算，已结算部分记录争议，不自动追回或抵扣新来源佣金。原登记误记通过关联申请和独立复核保留依据，不能声称更正代表外部退款。

金额门槛、次数／累计限额、高额复核起点、提醒时长、登记复核和岗位分离由显式规则草稿及另一身份批准。没有默认正式门槛，没有已发布规则时拒绝申请。日界使用北京时间，次数及累计口径为全部提交（包含驳回／撤销），页面和运行手册明确提示，正式发布前须核对。支付宝只保留原账户资料；启用申请须显式填写并复核平台资料政策，不把格式检查当官方验证。当前无额外扣减。

经办与用户撤销通过同一行锁及申请版本互斥。交接记录双方、付款情况、说明及接收时间；待接收期间不能登记。未知结果、部分金额或凭证不符均保留占用；只有确认未付且停止处理，或关联错误登记经过独立核查，才允许释放。完整登记及配置要求的独立复核后显示“已登记结算”。已结算记录不被静默逆转。

附件仍由文件领域私有保存，新增 `settlement_voucher` 用途；服务端验证真实 PNG/JPEG、归属与用途。敏感查看要求用途，按本人／本单审核／独占经办／复核授权，留下审计；传输不提供永久公开 URL。无微信／支付宝支付、转账、查单、付款回调、付款重试或付款调度。

代价：全局行锁及完整 JSON 状态适合当前实现规模，吞吐与增长须专项测试；未来关系化拆分必须保持来源、占用、幂等、审计及提交的一致性。不能通过删除流水或旧申请回退。
