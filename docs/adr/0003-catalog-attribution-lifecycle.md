# ADR 0003：产品发布快照、访问归因与独立领取

状态：本次实现采用；不代表待确认的运营参数已获业务确认；参数边界见 [M05–M07 需求追踪](../requirements/m05-m07.md)。

M05–M07 复用现有 PostgreSQL `crowd_state` 聚合和 `SELECT ... FOR UPDATE` 一致性边界，将 catalog 作为带 serde 默认值的新增分区，兼容旧文档。迁移 0004 扩展独立 `product_image` 文件用途，不删除任何历史数据或自动提高既有账户岗位。

规则位于 `catalog/domain`，应用编排位于 `catalog/north/local`，通过现有 community PostgreSQL adapter 持久化。HTTP 仅解析请求和组装稳定错误，不写 SQL；完成事件通过 `catalog/south/port/CompletionRecorder` 隔离。未接入可验签成果事件来源时不提供外部完成事件 HTTP 接口。

草稿、待审发布内容、已批准内容和领取快照分别保存。草稿更新使用乐观版本，领取／审批／下架在同一数据库行锁内串行，业务结果、幂等结果和审计一起提交；错误恢复原聚合后记录失败。同键异内容冲突。领取固定 CNY 整数分、任务／佣金规则版本、分类、产品、归因策略及触点；不产生可申请佣金或真实资金占用。

公开目录和领取每次以数据库服务端秒时间检查最新已生效批准版本，再验证有效期、分类、模板及规则，结束边界为排他。最新版本到期不回退旧版本。30 秒 worker 仅负责识别状态变化并持久化站内通知，故障不延迟下架或到期的请求拒绝。Web／小程序不保存目录缓存，小程序重新进入页面刷新目录。

匿名触点使用 24 字节随机凭证，客户端仅内存保存，登录后绑定一次可信身份；归属只从服务端推广码解析。首触／末触和窗口由规则管理员显式配置，领取固定版本，之后扫码不覆盖旧实例。内部完成事件按可信 source＋event 幂等、单任务唯一、时限和自推检查；归因申诉保留原触点，只记录裁定及待关联调整结论，不直接转移数字。

权衡：聚合行锁适合当前阶段验证一致性，但访问事件持续增长会扩大 JSON、审计和请求幂等数据，并串行化写入；本次不声称通过容量或压力验收。规模化前应拆分追加式触点、发布、领取和通知表，并通过迁移和业务唯一键保持同样一致性，明确留存与隐私策略后再清理，不能静默删除必要历史。

兼容：旧 `product_tasks` 规则仍可用于尚未迁移的旧定向码解析；新 catalog 同编号产品存在时以产品发布为准，不允许旧规则绕过新产品下架。新公开目录只返回新发布模型。未接入新目录的旧对象不会被虚构为已发布产品。
