# Crowd

Crowd 是面向产品推广与任务佣金管理的平台。目标流程为：产品上架与佣金标记 → 用户注册并获得个人推广码 → 领取任务与提交成果 → 平台审核并确认佣金数字 → 用户提交提现申请 → 平台人员在线下手动付款 → 系统登记处理结果及凭证。

用户端采用微信小程序，管理端采用 React Web，后端采用 Rust / Axum / SQLx，数据存储使用 PostgreSQL；平台中立的 TypeScript API 契约包供客户端使用。

## 需求与范围

以下为目标业务范围，M01–M12 已接入身份、资料、推广归因、产品发布、版本化定价／模板、任务执行、证据提交和质量审核。审核通过记录待数字入账确认；M13 台账、可申请余额、提现及人工结算尚未接入，全业务尚未验收。人工线下结算及无真实资金池的边界已确认；具体阈值、期限、复核策略和上线排期仍以业务确认结果为准。

| 业务领域 | 目标能力 |
| --- | --- |
| 用户与推广 | 注册登录、个人资料、个人推广码、推广归因 |
| 产品与定价 | 产品目录与上下架、佣金数字规则和版本 |
| 任务与审核 | 任务模板与资格、领取执行、证据提交、审核与质量判定 |
| 佣金与申请 | 数字变更记录、可申请数字、申请占用、提现审核 |
| 收款资料与结算 | 微信收款码上传、支付宝账户填写、人工处理、凭证登记与结果复核 |
| 运营支撑 | 通知、客服申诉、风控、后台权限审计、统计核对 |
| 平台保障 | 任务外部事件与契约、隐私治理、小程序体验、运行保障 |

目标角色包括用户、产品运营、任务审核、提现审核、人工经办、复核人员、客服、审计及系统管理员。用户端围绕产品、任务、推广码、个人中心和佣金数字提供入口；管理端按岗位划分操作权限与数据范围。

## 收款与人工结算边界

- 微信方式仅由用户上传本人收款二维码图片；个人推广码与微信收款码是不同对象。支付宝方式仅填写收款账户资料，按业务约定支持手机号或邮箱等形式，不要求支付宝授权登录，不采集支付密码或验证码。
- 不直接对接微信、支付宝支付或转账接口，不配置支付商户号、转账应用、商户证书或付款密钥；不自动提现、查单、重试付款或拉取官方支付账单。微信小程序登录与任务来源接入不属于支付对接。
- 系统没有真实资金池，不提供充值、存款、托管、代付或外部余额查询。佣金金额仅为业务标记数字，“申请占用”用于防止重复申请，不是实际资金冻结，也不要求金融借贷账本。
- 实际付款由授权人员在系统外手动进行。系统保存经办、金额、付款时间、登记时间、凭证及复核结果，展示“已登记结算”，不能宣称已获微信或支付宝官方到账验证；用户确认收款可另行记录，是否启用仍待确认。
- 图片识别和账户格式检查不代表官方实名、账户存在性或可收款验证。收款图、账户资料及人工凭证私有保存、按权限查看，提交申请时固定资料版本，后续修改不覆盖历史快照。
- 今后若引入自动支付或真实资金池，须单独确定新的需求范围，当前不预设相关必需接入工作。

## 业务设计约束

以下要求用于指导后续实现，不代表当前代码已提供相应能力。

- 推广访问与任务完成分开记录，扫码或点击不能直接产生可申请佣金。首期建议一层直接归因，不默认多级分佣或充值接单。
- 领取时固定产品、任务、佣金规则及归因快照，并一致性占用名额。活动计划数字上限为可选控制，不代表真实预算到账，不以外部资金到账作为上架或领取前置条件。
- 待审数字不可申请；已确认、未结算且未占用的数字才可申请。预计、待审、可申请、申请占用、争议暂缓和已登记结算应明确区分。数字按整数分保存、按元展示，比例、舍入和封顶规则明确。
- 数字增加、调整、占用、释放及登记结算保留关联记录，并与汇总一致更新；纠错新增关联调整，不能删除原记录、直接篡改汇总或因撤销登记声称线下款项已退回。
- 申请审核通过进入待人工处理，经办独占领取与用户撤销须互斥。线下结果不明进入待核实并保留占用，由人核查；确认未付款且停止处理后才释放本单占用，凭证登记及必要复核完成后转为已登记结算。
- 重复提交、领取、登记、复核及退回不得重复累计或释放数字。经办交接保留双方及线下付款情况；登记超时先查询原登记，不能重复线下付款。已线下结算后的任务失效或争议单独记录，不自动扣回外部款项。
- 每次接口请求校验身份、操作权限、资源归属、数据范围及当前状态，敏感资料最小化收集、脱敏展示并留审计。

## 开发

工具版本：Rust 1.97.1、Node 22、pnpm 11.22.0，使用 `devbox shell` 进入环境。

本地开发默认使用与 `../wekeeper` 相同的嵌入式 PostgreSQL 17，无需 Docker 或手动建库：

```bash
make install
devbox run -- make api-dev
# 另一个终端
devbox run -- make web-dev
```

`make api-dev` 等同 `make dev-embedded`，也可运行 `devbox run dev-embedded`。入口自动下载/复用 PostgreSQL 17 二进制、选择随机数据库端口与密码、创建临时 `crowd_dev` 库，执行与正式服务相同的 migration 和推广码 worker，然后启动 API。**正常退出删除临时数据，每次重启重新建库**；安装缓存保留在 `~/.theseus/postgresql`。SIGKILL、系统崩溃等异常中断不保证完成清理。

嵌入式入口忽略 `CROWD_DATABASE_URL` 和外部测试库 URL，不自动读取 `.env`，不会连接已有应用数据库。微信与其他业务配置仍由同一终端 export；不提供绕过微信身份校验的本地用户。开发管理员自动初始化；协议发布与岗位配置见 [M01–M04 运行记录](docs/runbooks/m01-m04.md)，临时库重启后需重新发布协议。

Web 访问 http://127.0.0.1:5173；API 默认监听 127.0.0.1:8080。`CROWD_BIND_ADDR` 可修改 API 端口，嵌入式入口只接受环回地址。`CROWD_API_ORIGIN` 可修改 Vite 代理上游，`RUST_LOG` 控制日志。详见 [嵌入式开发与验证](docs/runbooks/embedded-postgres.md)。

需要持久化开发数据或使用外部 PostgreSQL 时显式选择：

```bash
cp env.example .env
# 填写 POSTGRES_PASSWORD，例如使用 openssl rand -hex 24 的结果。
docker compose --env-file .env -f compose.yaml -f compose.dev.yaml up -d postgres
export CROWD_DATABASE_URL='postgres://crowd:替换密码@127.0.0.1:5432/crowd'
devbox run -- make api-external
```

`api-external` 与生产二进制要求显式数据库 URL；URL 特殊字符须百分号编码，远程数据库按环境配置 TLS。Compose 仍部署独立 PostgreSQL，嵌入式库仅为 Cargo dev-dependency。

小程序运行 `make miniapp-dev`，在微信开发者工具导入 `frontend/apps/miniapp/dist/dev/mp-weixin`；发布构建为 `pnpm --dir frontend --filter @crowd/miniapp build`，产物在 `dist/build/mp-weixin`。先在 manifest.json 填写自己的微信 AppID。当前个人中心访问 API；构建时设置 `VITE_API_ORIGIN`，生产配置微信合法 HTTPS 请求/下载域名。微信 AppSecret 仅配置在服务端。初始化管理员、发布协议及二维码域名配置见 M01–M04 运行记录。

## 检查

```bash
make check-web
devbox run -- make check-backend
devbox run -- make test-embedded
devbox run -- make test-business
```

前端检查包含契约类型、两端类型检查、lint 和生产构建；后端包含格式、编译、Clippy、领域与 HTTP 契约测试。`test-embedded` 验证实际嵌入式入口的迁移、信号退出、端口冲突清理与配置隔离（需 Python 3）；`test-business` 自动创建独立嵌入式测试库，执行此前需手动准备数据库的集成测试并清理。普通后端测试默认跳过数据库测试，跳过不代表通过。

## Docker

配置 `.env` 后执行 `make compose-up`，访问 http://127.0.0.1:8088。仅 Web 绑定环回端口；开发覆盖文件额外开放数据库/API 的环回端口。`make compose-down` 保留数据库卷。

生产设置 `API_IMAGE`、`WEB_IMAGE` 为发布镜像，使用 `docker compose --env-file .env -f compose.yaml up -d --wait`。源码构建上下文必须为仓库根目录。Web 镜像只构建 Web 和 contract，小程序独立发布。公网部署需自行配置 HTTPS 入口。

原骨架检查保留在 [骨架验证记录](docs/runbooks/foundation-validation.md)；新增业务检查及未验证项见 [M01–M04 运行记录](docs/runbooks/m01-m04.md)。

### 管理员登录

Web 首页提供管理员账号密码登录，也可切换小程序一次性票据。`make api-dev` 的嵌入式 PG 自动创建 `admin`：开发后端控制台直接显示本次随机临时密码，也可按 `credential_file` 路径读取私有文件；或预先设置 `CROWD_DEV_ADMIN_PASSWORD`（12–128 字节）。退出后账号和凭据文件随临时数据库清理。

外置数据库可同时设置 `CROWD_BOOTSTRAP_ADMIN_USERNAME` / `CROWD_BOOTSTRAP_ADMIN_PASSWORD` 首次创建管理员，创建后移除；不会覆盖已有账号密码或权限。详见 [开发运行手册](docs/runbooks/embedded-postgres.md) 和 [M01–M04 手册](docs/runbooks/m01-m04.md)。

### Web 管理工作台

管理端现使用 Ant Design Pro 布局，提供工作台、业务规则、用户与权限、推广码管理、审计日志和使用指南，菜单按岗位展示。开发、浏览器回归与实现范围见 [Web 管理端运行手册](docs/runbooks/web-console.md)。
